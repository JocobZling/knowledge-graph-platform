## 2. AI / 大模型 Top News
### 2.1 AgentCore Web Answer 正式GA
**主体：AWS｜2026-11-05｜新颖度5/5｜GA。** [官方原文](https://aws.amazon.com/blogs/machine-learning/getting-started-with-web-answer-on-amazon-bedrock-agentcore/)。
Web Answer将检索、信息综合与引用整合为一次工具调用，并可作为AgentCore Gateway工具使用。其价值是降低开发者维护检索管道和引用映射的复杂度，**不是保证所有引用均准确或结果一定最新**。建议为外部信息设置域名白名单、发布日期校验、引用可达性校验与无证据拒答。金融内网不得直接把外部检索内容写入业务系统。
### 2.2 多租户AI分析：把权限留在数据层
**主体：AWS｜2026-11-05｜新颖度5/5｜架构实践。** [官方原文](https://aws.amazon.com/blogs/big-data/deliver-multi-tenant-ai-analytics-at-scale-with-agentcore-and-lake-formation/)。
Agent可通过MCP和数据工具生成查询，但多租户应用的核心问题是确保每个身份只访问获授权的行、列和表。AWS给出AgentCore与Lake Formation的受控分析设计。对现有PostgreSQL/Java项目，可借鉴“用户身份→可信权限上下文→受限查询→独立回读”，无需迁移云平台。**仅靠Prompt禁止越权不构成授权机制。**
### 2.3 Copilot代码审查增加反馈采纳与分类指标
**主体：GitHub｜2026-11-05｜新颖度4/5｜API增强。** [官方原文](https://github.blog/changelog/2026-11-05-usage-metrics-api-adds-code-review-details-and-addressed-rate/)。
仓库日粒度指标新增`total_comments_evaluated`、`total_comments_addressed`，并按严重程度、审查级别、问题类型和自定义方式细分。采纳/处理率=addressed/evaluated，但“回复未来修复”也可能计为已处理，**不能等同于缺陷已修复或代码质量提升**。仅在PR合并时评价评论，注意时间归属。
### 2.4 Copilot API标记遥测与版本缺口
**主体：GitHub｜2026-11-05｜新颖度4/5｜API增强。** [官方原文](https://github.blog/changelog/2026-11-05-usage-metrics-api-flags-telemetry-and-version-gaps/)。
新增`client_telemetry_present`、`usage_metrics_requirements`、`missing_client_telemetry_user_count`及`below_usage_metrics_minimum_user_count`。代理、网络策略、禁用遥测和旧版本均可能导致指标缺口。**null/缺字段表示未知，不能按0处理；不同缺口人群可能重叠。** 对受限内网的AI效果报表尤其重要。

## 5. Agent Ecosystem
### 5.1 MCP / Tool Calling：引用工具不等于可信事实
Web Answer可减少工具编排，但Agent最终输出应保留`source_url`、`published_at`、`retrieved_at`、`claim_id`和`verification_status`。不可信网页文本不得提升工具权限。
### 5.2 Agent / Workflow：多租户隔离优先服务端执行
查询链路应为“登录态→Java权限范围→参数白名单→SQL查询→独立核验”，而不是“LLM自行声明user_scope”。若未来增加Browser Agent，也应在页面会话与API层分别检查权限。
### 5.3 Agent Testing：评估指标必须有覆盖率分母
模型审查的“评论被处理率”、工具成功率、Golden Set通过率是不同指标；当Trace缺失或遥测缺口存在时应标记`UNKNOWN`，不应直接判为通过。
**本周最值得体验：** 使用Mock外部搜索结果制造“有引用但引用不支持结论”的场景，验证拒答与人工复核。  
**Agent实践启发：** 把来源可追溯、数据授权、结果核验、观测完整性分为四道独立门禁。

## 9. 今日实战
为测试经理智能助手增加`evidence_status`：`VERIFIED`、`UNVERIFIED`、`STALE`、`UNAUTHORIZED`。统计执行数量由Java可信接口回读；外部资料引用仅供解释，不得作为内部数据库查询结果。统一Trace记录`user_id`（脱敏）、`capability_id`、`query_period`、`source`、`policy_version`、`verified_at`。

## 10. Today Worth Thinking
**如果Agent的回答有引用，但引用页面并不能支持其关键数字，应该算成功吗？** 建议答案为否：引用存在率与引用支持率应分别计量；业务数字仍以授权数据源的独立核验为准。

## 11. 30分钟 Action
在Mock环境准备6条Golden Set：①合法查询且有证据→VERIFIED；②引用无关→UNVERIFIED；③引用过期→STALE；④跨系统越权→UNAUTHORIZED；⑤工具返回成功但数据库不一致→UNVERIFIED；⑥遥测缺失→UNKNOWN。前10分钟构造样本，后15分钟执行，最后5分钟核对Trace。完成标准：每条均有预期与实际结果，异常场景不泄露数据。

## 13. 我的备注：金融测试、Agent Testing与智能测试平台
**测试经理智能助手：** 维持Vue3 iframe + Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL。优先做执行统计/负责人查询的服务端权限过滤、事实核验和Golden Set；暂不引入云端Web Answer。后续对话生成查询条件时，服务端只接受白名单字段与明确时间范围。
**日志脱敏检测平台：** 参考GitHub凭据检测器的伴随条件与上下文过滤，继续同时衡量Precision、Recall与关键漏报。将规则版本、Prompt版本、AI精筛结果、人工复核证据和扫描轮次关联，避免误报下降掩盖漏报。
**Agent Testing：** 增加Citation Support Rate、Authorized Query Rate、Verified Task Success Rate、Trace Coverage Rate；任何UNKNOWN都不得被自动计入成功。

**今日结论：有引用不代表事实正确，有工具权限不代表数据可见，有使用量指标不代表观测完整。**
