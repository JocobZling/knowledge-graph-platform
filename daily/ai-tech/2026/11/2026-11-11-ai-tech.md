## 1. 今日摘要
① **Gemini 4 Carbon**（GitHub，11/10）正式进入Copilot，支持复杂编码、Agent任务；按供应商标价计费，逐步开放。② **Claude Fable 5.2**（GitHub，11/09）进入Copilot，企业启用默认关闭；关键风险是默认需要保留提示词及输出用于安全分类，符合条件的企业可申请限时零留存例外。③ **Actions工作流日志密钥扫描**（11/09）进入公开预览，任务完成后扫描日志并关联告警，但不回填历史日志、不覆盖自定义规则或已掩码密钥。④ **Dependabot闲置仓库策略**（11/10）公告：12月8日起大部分一年无活动仓库暂停告警，例外需核对安全策略。**判断：** Agent治理的重点是模型选型与数据流、日志安全、供应链持续监控的组合，而不是只看模型榜单。

## 2. AI/大模型 Top News
### 2.1 Gemini 4 Carbon在GitHub Copilot正式可用
**主体：GitHub/Google｜发布2026-11-10｜新颖度5/5｜Copilot平台GA，非原厂首发证明。**  
官方：https://github.blog/changelog/2026-11-10-gemini-4-carbon-in-github-copilot/  
GitHub将Gemini 4 Carbon加入Copilot模型选择器，定位复杂编码、Agent及推理任务，覆盖VS Code、Copilot CLI、coding agent、JetBrains等多入口；向Pro+、Max、Business、Enterprise逐步推出。企业管理员可通过模型策略控制启用，按供应商标价进行用量计费。**限制：** 官方公告未提供跨模型独立基准或银行内网部署能力，不能直接推断比DeepSeek V4更适合现有系统。**测试建议：** 在同一Java代码修改任务上比较工具调用次数、编译通过率、回归通过率、耗时和费用。
### 2.2 Claude Fable 5.2接入Copilot，数据留存要求成为选型门槛
**主体：GitHub/Anthropic｜发布2026-11-09｜新颖度5/5｜Copilot GA。**  
官方：https://github.blog/changelog/2026-11-09-claude-fable-5-2-in-github-copilot/  
GitHub称该模型在早期内部测试中完成更多复杂多步骤编码任务，且较Fable 5.1使用更少步骤/工具调用；未公布可独立核验的具体胜率。Business/Enterprise管理员需主动启用，默认关闭。**重大合规差异：** 默认保留提示词与输出供Anthropic安全分类，不用于训练；符合条件企业可申请截至2026年底的限时零数据留存例外，后续须关注EFS要求。**金融建议：** 未经合规确认不上传代码、日志或客户数据；留存策略与模型性能应并列为准入条件。
### 2.3 GitHub Actions工作流日志进入密钥扫描范围
**主体：GitHub｜发布2026-11-09｜新颖度5/5｜Public Preview。**  
官方：https://github.blog/changelog/2026-11-09-secret-scanning-detects-secrets-in-github-actions-workflow-logs/  
工作流结束后按供应商密钥模式扫描日志，告警链接回对应执行日志；支持的密钥可进行有效性检查。仅面向具备指定安全许可的Enterprise Cloud环境，默认关闭；仅扫描开启后的新日志，不回填历史。**盲区：** 通用/自定义模式、AI检测和已掩码密钥不在预览范围；预览期告警不主动通知。**金融建议：** 不可仅依赖平台扫描，应在流水线打印前脱敏，并定期巡检告警列表。
### 2.4 Dependabot将暂停大部分长期闲置仓库的告警
**主体：GitHub｜发布2026-11-10｜新颖度4/5｜未来策略变更。**  
官方：https://github.blog/changelog/2026-11-10-dependabot-alerts-will-pause-on-inactive-repositories/  
自12月8日起，大部分过去一年无推送等活动的仓库将暂停Dependabot告警，历史告警归档不删除；新的push或重新启用可恢复。企业强制安全配置等存在例外；不适用于GitHub Enterprise Server。**风险：** 低频维护的测试工具、规则包、旧MCP服务可能长期不更新，却仍被引用。建议对关键仓库启用强制安全配置并建立外部资产台账，不能将“无新告警”误判为“无漏洞”。

## 5. Agent Ecosystem
**5.1 Agent / Tool Calling：模型切换要有可比较的任务证据。** 对同一Java Capability开发任务固定输入、仓库版本、权限、测试集，比较修改范围、工具调用、失败重试和成本；模型上架GA不等于企业可直接放行。  
**5.2 Skill / MCP / Workflow安全治理：** Agent依赖、MCP服务及流水线日志分别检查供应链来源、执行权限、敏感信息输出；在CI中使用假密钥样本验证脱敏，不把真实凭据写入测试日志。  
**5.3 Browser Agent与审计：** 即使浏览器或编码Agent报告成功，仍需由可信接口核验业务状态；记录Trace与敏感字段屏蔽结果，避免将Token、用户身份信息写入日志。  
**本周最值得体验：** 对一个脱敏Java Mock项目运行两种模型/配置的同任务对照评测，收集编译、单测、权限和日志脱敏结果。  
**Agent 实践启发：** 模型能力、数据留存、日志泄露和依赖安全告警属于四种不同的治理门禁，不能以单一成功率代替。

## 6. 开源推荐
**项目：[gitleaks/gitleaks](https://github.com/gitleaks/gitleaks)**。**Stars：本次未获得可靠实时快照，不编造；License：MIT（正式使用前复核仓库许可证）。** 核心能力：Git仓库、文件及文本中的密钥模式检测，支持CI与自定义规则。推荐理由：可在脱敏环境为AI编程输出、构建日志和Agent Trace建立预提交/流水线检查。**边界：** 模式匹配不能保证发现所有泄露，真实密钥必须轮换而非仅删除日志。

## 7. 企业实践
**GitHub：将CI运行日志纳入安全发现闭环（11/09）。** 做法：工作流完成后扫描日志，将命中项关联回执行记录和仓库告警；可对部分密钥做有效性校验。**效果：** 官方确认预览功能，但未披露可独立核验的实际泄露下降率。**可借鉴：** 日志脱敏检测平台在工程日志之外增加CI日志扫描接入、任务来源和告警回溯；预览不支持的通用模式需要自有规则补足。

## 8. 今日工具推荐
**[Gitleaks](https://github.com/gitleaks/gitleaks)**：先用完全虚构的测试Token与脱敏样例验证检测器；将结果转成规则版本、命中行、上下文摘要和处置状态，不向外部服务上传内网日志。

## 9. 今日实战
**为AI编程/Agent流水线设计日志安全门禁：** 在测试环境构造四类输出：模拟凭据、已掩码凭据、普通业务ID、含恶意指令的工具返回。分别检查敏感值是否在日志落盘前脱敏、检测规则是否误报、告警是否指向正确任务、Prompt Injection是否被当作普通不可信文本处理。所有样本使用虚构值。

## 10. Today Worth Thinking
**一个Coding Agent代码修改通过所有单测，但把API Token写入CI日志，这次任务算成功吗？** 不算完整成功。业务正确性与信息安全必须分别验收；日志中的真实密钥需要轮换，并核查可访问范围和保留副本。

## 11. 30分钟 Action
| 时间 | 操作 | 产出 |
|---|---|---|
| 0—10分钟 | 准备4条虚构日志：明文模拟密钥、掩码密钥、普通ID、工具异常堆栈 | Mock数据 |
| 10—20分钟 | 用现有日志规则或本地Gitleaks扫描，核对脱敏与命中 | TP/FP/FN/TN |
| 20—30分钟 | 检查Trace关联、误报与漏报，记录规则版本 | 4条PASS/FAIL |
**完成标准：** 虚构密钥被检测，正常ID不误报，所有结果可追溯；不使用真实银行凭据。

## 13. 我的备注：金融测试、Agent Testing与智能测试平台
**测试经理智能助手：** 继续Vue3 iframe + Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL的一期路径；优先内网联调与Capability Registry。新增“模型/工具输出日志脱敏”检查，明确Trace中的user_id、查询参数和模型响应脱敏范围。模型选择需先过数据留存与内网出口审查，不因Copilot模型上架而调整架构。  
**日志脱敏检测平台：** 研究将CI/CD日志作为新的扫描来源，保持现有正则/Key-Value/AI精筛；对失败重扫和继续扫描沿用执行轮次、幂等、同条件复扫机制。  
**Agent Testing：** 建议跟踪Secret Leakage Detection Rate、False Positive Rate、Trace Redaction Coverage、Model Data-Retention Compliance及Verified Task Success。**结论：** Agent质量不仅是“任务做对”，还包括“数据不外泄、权限不越界、证据可回溯”。
