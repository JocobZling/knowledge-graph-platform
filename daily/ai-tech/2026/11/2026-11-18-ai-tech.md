# AI 与 Agent 每日简报 v2｜2026-11-18

## 1. 今日摘要
11月17日新发布集中在模型、Agent评估和事件驱动协作。最值得测试团队关注的是Copilot Evals：Skill、MCP和自定义Agent均可建立可重复评估。已读取11月11—17日七篇日报的主题与摘要，常见索引路径未找到；以下均为新增发布，非此前模型退役或扫描配置的重复报道。

## 2. AI / 大模型 Top News
### 2.1 GPT-6.2 Astra与Sol（OpenAI，11/17，新颖度5/5）
进入ChatGPT Work、Codex和API，官方强调专业产出、编码、计算机操作及效率。官方社区称Astra在其评估中的每任务成本低于GPT-6 Astra的三分之一，此为厂商评估而非银行场景实测。Sol面向日常多步骤工作。建议在外网脱敏仓库用固定任务比较遗漏修改、测试通过率、总耗时，不将外部API接入受限内网。[官方公告](https://community.openai.com/t/gpt-6-2-astra-and-sol-are-now-available/1417531)；[官方发布索引](https://openai.com/research/index/release/)。
### 2.2 Copilot Evals公开预览（GitHub，11/17，新颖度5/5）
支持创建、运行和比较Skill、自定义Agent、MCP工具评估，检查结果及执行过程，每次运行需批准，使用Vally本地评估引擎。支持VS Code、CLI和Copilot app。与此前UAEF不同，这是开发工具自身的评估入口；本地评估引擎不代表模型推理离线。[官方](https://github.blog/changelog/2026-11-17-github-copilot-evals-is-now-in-public-preview/)。
### 2.3 MAI Code 2与Flash（Microsoft/GitHub，11/17，新颖度5/5）
前者面向复杂调试、多文件实现和重构，后者面向解释、局部修改及快速迭代，两者进入Copilot多个入口，按用量计费。模型定位不等于实际质量保证，应固定测试和成本口径。[官方](https://github.blog/changelog/2026-11-17-mai-code-2-and-mai-code-2-flash-in-github-copilot/)。
### 2.4 GitHub Event Streams（GitHub，11/17，新颖度5/5）
通过持续连接接收PR审查、提交、冲突、合并及检查状态事件，无需公开Webhook接收端；需候补审批，属预览。可减少轮询，但断线补偿、重复事件与权限仍需测试。[官方](https://github.blog/changelog/2026-11-17-github-event-streams-is-now-in-preview/)。

## 5. Agent Ecosystem
Skill/MCP：把业务语义、参数、权限和预期证据写成测试契约，避免只验证最终文本。
Workflow/编排：事件驱动适合长任务和异步回调，但需要事件ID、执行轮次、断线补偿和幂等。
Browser Agent/Tool Calling：浏览器和API均应验证真实业务状态；集中审计应先脱敏。
**本周最值得体验：** Copilot Evals或本地等效评估，针对一个查询Skill构建正常、歧义、越权三类任务。
**Agent实践启发：** 能力注册时同步提交验收用例，而非集成后才补测。

## 7. 企业实践
GitHub与Microsoft将Copilot跨客户端审计流接入Agent 365，管理员可查看会话、提示、响应及工具调用，并结合Purview和Defender风险信息。官方未公布量化收益。金融平台可借鉴统一审计事件，而不是直接复制云服务；避免完整敏感Prompt进入日志。

## 8. 今日工具推荐
Promptfoo：在脱敏Mock中复用同一输入与断言，比较工作流版本；内网通过获准的工作流接口调用模型，不直接绕过限制。

## 9. 今日实战
定义能力准入用例：capability_id=query_execution_summary；input=查询本月执行数；expected_tool=query_execution_summary；expected_scope=SELF；expected_count=12（虚构）；forbidden=跨用户数据。工具选择、授权、结果数量分别断言，任一关键断言失败即不准入。

## 10. Today Worth Thinking
一个Agent能接入100个API，但每次新增接口都需要重写Prompt和路由，是否真的具备可扩展性？关键是业务能力契约、发现机制和回归用例，而非接口数量。

## 11. 30分钟 Action
0—10分钟：选择一个现有查询API，提取输入、输出、权限和错误码。
10—20分钟：编写正常、缺参、歧义、越权、空结果五条Mock验收。
20—30分钟：执行并记录预期工具、实际结果、独立断言。
交付物：一个能力登记文件和五条测试样本；不要求部署新框架。

## 13. 我的备注
测试经理助手：主工程继续保障年底交付；探索工程重点验证业务能力注册与自动发现，不直接把所有Web API暴露给Agent。每个能力登记业务描述、Schema、授权、负责人、版本和Golden Set，保留Java执行层及Dify模型入口。归档仅使用脱敏通用建议。

Agent Testing：新增能力准入覆盖率、参数正确率、权限阻断率、事件重放一致性及业务结果真实性。
