## 2. AI / 大模型 Top News
### 2.1 GPT-6 Cyber：能力增强与授权边界同时进入评测
**OpenAI｜2026-11-05｜新颖度5/5｜限制访问的产品发布。** [官方公告](https://openai.com/index/introducing-gpt-6-cyber/) · [系统卡](https://deploymentsafety.openai.com/gpt-6-cyber)。
OpenAI披露ExploitGym成绩48.5%，对照GPT-5.6 Cyber的32.1%；在其特定越界测试中，无部署提示时99.93%未攻击范围外服务，有提示时100%。这是特定测试集的结果，**不是现实场景零越权保证**。官方将模型的网络安全能力评为Critical，Daybreak Red采取身份核验、组织控制和访问限制。对金融测试的启发不是申请攻击能力，而是把范围约束测试做成独立指标：允许工具、目标资源、时间窗口、批准人及服务端强制检查。

### 2.2 BioBasicsBench：真实原始证据比精美图表更难
**OpenAI × Ligo｜2026-11-06｜新颖度5/5｜新研究基准。** [官方研究](https://openai.com/index/measuring-how-ai-agents-handle-wet-lab-science/)。
100项任务覆盖图像、仪器数据、CSV、实验记录与视频；37种模型/思考配置、每任务5次，总计18,500次结果。xhigh下GPT-6 Astra平均奖励66.7%（95% CI 60.3–73.1），GPT-5.6 Sol为43.8%。**平均奖励不是完整任务成功率。** 研究展示模型可能忽略反证、误认对照组、计数高估约12%。金融Agent处理扫描报表、截图和日志时同样需要原始证据定位、冲突检测与不足证据拒答。

### 2.3 Google Cloud Z4M正式GA：隔离Agent执行环境的基础设施参考
**Google Cloud｜2026-11-06｜新颖度4/5｜基础设施GA。** [官方公告](https://cloud.google.com/blog/products/compute/storage-optimized-z4m-machine-series-are-ga)。
Z4M提供虚拟机和裸金属，最高168,000 GiB本地SSD、400 Gbps RDMA，官方将大规模隔离沙箱列为应用之一。其高吞吐更适合大型AI存储、KV缓存和密集沙箱，不代表普通银行测试助手需要该规格。需要留意区域可用性、维护时停机策略和数据持久性；**硬件隔离能力不等于业务权限自动正确**。

### 2.4 Mito：异步多模型编排与自动质量门禁
**Google Cloud / Mito｜2026-11-06｜新颖度4/5｜企业工程案例。** [官方案例](https://cloud.google.com/blog/products/media-entertainment/how-mito-orchestrated-5000-plus-ai-assets-for-a-world-cup-tv-spot)。
Mito在Movistar Plus+广告项目中生成超过5,000项素材（约1,000条视频、约65轮迭代），使用Cloud Run Java服务、Pub/Sub任务总线、Cloud Storage和PostgreSQL等组件。后台任务限流、有限重试、每任务明确结局；另使用Gemini评测Harness验证Agent输出是否符合意图。企业披露，不能将广告案例的效率推断为通用生产率。与日志扫描多服务器任务的异步聚合有可借鉴的架构共性。

## 5. Agent Ecosystem
### 5.1 Agent / Tool Calling：范围约束必须在服务端生效
GPT-6 Cyber的范围测试提醒：即使模型在基准上遵守限制，MCP/Skill的工具调用仍需由Java Capability API验证用户、资源和动作的交集；模型自报“已授权”无效。跨工具链需测权限累积与越界请求。
### 5.2 Workflow / Agent Testing：原始证据与反证优先
BioBasicsBench揭示模型可能看到矛盾信息仍下结论。Browser Agent应把截图、接口响应、数据库回读分别保存；扫描PDF应保存文档版本、页码和数值定位。遇到证据冲突标记UNVERIFIED。
### 5.3 编排 / 安全治理：异步任务必须有可终结状态
Mito的Pub/Sub与有限重试提醒：Agent长任务应具有task_id、attempt、deadline、幂等键、取消/超时和最终状态。并发Worker的状态聚合不能依赖模型自由文本。
**本周最值得体验：** 为一个Mock Capability配置“允许读取系统A，禁止系统B”的服务端策略，模拟Agent连续跨工具查询，验证拒绝和审计。
**Agent 实践启发：** 将模型是否遵守规则与服务端是否真正阻断越界分成两套测试。

## 9. 今日实战
为测试经理智能助手设计可信验证契约：
```json
{
  "trace_id": "demo-20261107",
  "capability_id": "query_execution_summary",
  "authorized_systems": ["SYS_A"],
  "requested_system": "SYS_B",
  "policy_result": "DENY",
  "tool_executed": false,
  "evidence_status": "VERIFIED_DENIAL"
}
```
**示例数据。** authorized_systems应来自可信服务端登录态；不能由Dify或LLM生成。对拒绝结果也应核验“工具未执行、未泄露数据”。

## 10. Today Worth Thinking
**如果Agent在99.93%的基准场景中不越界，企业能否放弃服务端权限检查？** 不能。基准行为指标不是权限边界；真正的授权由服务端执行，且应以拒绝后的真实副作用为证据。

## 11. 30分钟 Action
**目标：6条跨工具权限和证据冲突Golden Set。**
| Case | 输入 | 预期 |
|---|---|---|
| B01 | 授权系统A查询 | VERIFIED |
| B02 | 未授权系统B查询 | DENY，无Tool执行 |
| B03 | 模型伪造ALL权限 | DENY |
| B04 | 工具返回旧周期数据 | STALE |
| B05 | 页面数值与数据库冲突 | UNVERIFIED |
| B06 | 工具超时后重试成功但重复写入 | 幂等阻断 |
**0—10分钟：** Mock准备；**10—20分钟：** 执行；**20—30分钟：** 核对Trace、数据库和拒绝证据。完成标准：6条有PASS/FAIL及真实副作用核验。

## 13. 我的备注：金融测试、Agent Testing与智能测试平台
**测试经理智能助手：** 维持Vue3 iframe + Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL。优先执行统计/负责人查询的权限交集与事实回读；不要因安全专用模型发布而调整一期模型架构。新增工具前先落实服务端拒绝测试和Golden Set。
**日志脱敏检测平台：** 借鉴Mito的异步队列与有限重试：report/server分别保留execution_epoch、attempt、event_id，继续扫描与失败重扫必须防止旧回调覆盖新轮次。AI精筛遇到冲突证据应转人工复核。
**Agent Testing：** 增加Out-of-Scope Block Rate、Evidence Conflict Detection、Verified Task Success、Idempotent Retry Pass Rate。将“模型报告遵守规则”与“后端真正阻断越界”分别统计。

**今日结论：Agent可信执行的基础是可强制的边界、可定位的原始证据和可验证的业务副作用。**
