## 1. 今日摘要
本期四项独立重点：（1）OpenAI 11月13日发布ChatGPT Wallet，Agent无法获得用户真实卡信息，逐笔购买需用户安全确认，初期仅面向美国符合条件的Pro用户；（2）OpenAI 11月10日公开研究基础设施Control Room，可集中阻断推理任务，官方报告在停止决策后35秒内停止输出；（3）Google 11月11日推出Gemini Decisions API，单次支持最多1000个是非/选择/评分问题，面向多模态批量判定；（4）AWS 11月13日介绍NVIDIA NeMo Switchyard对Coding Agent请求的模型路由工程方案。**共同主线：将授权、停止、判定和路由从自由生成中抽离，形成可审计的控制层。**

## 2. AI / 大模型 Top News
### 2.1 ChatGPT Wallet：Agent支付必须逐笔授权
**主体：OpenAI｜发布时间：2026-11-13｜性质：有限范围产品发布｜新颖度5/5**  
官方：https://openai.com/index/introducing-chatgpt-wallet/

OpenAI宣布与American Express、Mastercard、Visa合作推出ChatGPT Wallet。用户先绑定卡片，Agent在购买时不接触真实卡详情；每笔购买前由用户确认商品、总额和卡片，并使用生物识别等安全检查，支付网络提供代替真实卡信息的支付令牌。初期通过dots向美国ChatGPT Pro订阅者有限开放。官方描述的未来预授权额度、品类和时间窗口是**未来方向**，不是当前已经普遍可用的自动扣款能力。  
**价值：** 金融业务写操作可借鉴“草案→确认→授权凭证→执行→交易回读”，不要让模型直接接触敏感支付凭证。**限制：** 不代表已支持国内银行业务、企业内网或任意商户。

### 2.2 Control Room：研究Agent工作负载的集中停止机制
**主体：OpenAI｜发布时间：2026-11-10｜性质：内部研究基础设施技术披露｜新颖度5/5**  
官方：https://openai.com/index/control-room/

Control Room将研究任务、推理引擎与集中策略服务关联。任务启动取得job_id，推理引擎在生成前向控制服务检查任务是否允许继续；被停止的任务不再获得模型输出。官方报告从决定干预到停止输出在35秒内，并设计了控制服务不可用时的失效保护。**这是OpenAI内部研究环境披露，不是可直接安装的通用开源产品或所有外部API的SLA。**  
**价值：** 对高并发Dify工作流，建设任务级cancel、超时、预算和熔断控制；但“停止模型输出”不自动撤销已提交的数据库写操作。

### 2.3 Gemini Decisions API：多模态批量判断
**主体：Google｜发布时间：2026-11-11｜性质：新API｜新颖度5/5**  
官方：https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/

Google介绍由Gemini Decision 1驱动的Decisions API，可在单次请求中评估最多1000个是非、选项和Rubric评分问题，覆盖文本、图像、音频、视频和PDF。该产品定位于结构化决策，不应等同于自动化业务审批。  
**价值：** 对日志脱敏检测的500条固定样本，可以借鉴批量判定的接口形态；但必须比较误报、漏报、成本、延迟与敏感数据合规，不能直接把银行日志上传外部API。

### 2.4 NeMo Switchyard：Coding Agent请求按任务路由模型
**主体：AWS/NVIDIA｜发布时间：2026-11-13｜性质：技术方案，非新GA｜新颖度4/5**  
官方：https://aws.amazon.com/blogs/machine-learning/route-coding-agent-requests-to-the-right-model-on-amazon-bedrock-with-nvidia-nemo-switchyard/

AWS发布基于NVIDIA NeMo Switchyard与Bedrock的Coding Agent模型路由实践，目标是针对不同请求选择合适模型，而非所有任务都交给最高成本模型。文章提供工程集成思路；实际收益取决于任务分布、路由准确率、回退策略与评测基线，不能将文章示例直接外推到金融Java项目。  
**价值：** 当前仅DeepSeek V4的内网不必引入额外路由层；未来多模型可用时，以业务Golden Set作为路由准入条件。

## 5. Agent Ecosystem
### 5.1 Agent / Tool Calling：用户授权不能由模型自我声明
Agent生成待确认草案，Java服务端绑定可信身份、业务对象、操作范围、有效期和幂等键；用户确认后才能调用写工具。审批凭证应与具体参数摘要绑定，防止确认后偷偷改变金额或目标对象。

### 5.2 Workflow / 安全治理：取消推理不等于撤销副作用
区分PENDING、APPROVED、EXECUTING、CANCEL_REQUESTED、CANCELLED、COMPLETED和UNKNOWN。取消后需检查工具是否已提交；已完成写入的操作只能走补偿或人工处理，不能宣称“撤销成功”。

### 5.3 Skill / MCP / Browser Agent：结构化契约优先
Skill描述任务操作规范，MCP标准化工具接口，Browser Agent处理界面操作；真实权限和状态回读仍应由可信后端负责。对于页面操作应检查授权范围、截图脱敏与最终数据回读。

**本周最值得体验：** 在本地Mock里模拟“用户批准创建任务，但Agent在执行前收到取消”，验证不会产生任务记录；另模拟“已提交但回调超时”，验证返回UNKNOWN而非错误重试造成重复创建。  
**Agent 实践启发：** 高风险操作必须把“意图、授权、执行、副作用、最终验证”分成不同状态和证据。

## 7. 企业实践
**OpenAI与支付网络合作的Agent支付架构。** 做法：用户每笔交易前确认商品、金额和支付方式；支付网络提供令牌，Agent不直接获取真实卡详情；商户仍负责定价、履约和售后。效果：官方已披露产品机制与有限开放范围，但没有提供可独立验证的普遍支付成功率或欺诈率下降数字。可借鉴：金融Agent将“授权凭证”和“执行结果”作为两个独立可审计对象。来源：https://openai.com/index/introducing-chatgpt-wallet/

## 8. 今日工具推荐
**Playwright MCP**（https://github.com/microsoft/playwright-mcp）。在本地Mock任务页上测试Agent点击、表单输入、错误提示与最终任务ID回读；不需要连接真实业务系统。先核对依赖与权限，浏览器操作截图和Trace必须脱敏。

## 9. 今日实战
**任务创建授权与取消契约（虚构样本）：**
```json
{
  "trace_id": "mock-20261116-001",
  "operation": "create_test_task",
  "draft_hash": "mock-hash",
  "user_approval": "APPROVED",
  "idempotency_key": "mock-key-001",
  "cancel_requested": true,
  "write_committed": false,
  "verified_state": "CANCELLED"
}
```
服务端验证批准的草案哈希、操作者身份、审批时效和幂等键；取消与写入并发时应以真实提交状态决定最终状态。禁止让LLM自行填充user_approval或verified_state。

## 10. Today Worth Thinking
**Agent在用户确认后发起创建操作，网络超时且用户点击取消，系统是否能直接回复“已取消”？** 不能。必须先确认写操作是否已提交；状态未知时应返回UNKNOWN并按幂等键查询，而非盲目重试或宣称撤销。

## 11. 30分钟 Action
| 时间 | 操作 | 产出 |
|---|---|---|
| 0—10分钟 | 构造待确认、批准、超时、取消、重复提交五条Mock | 测试数据 |
| 10—20分钟 | 执行状态机与幂等校验 | Trace与返回码 |
| 20—30分钟 | 回读真实任务ID和数据库状态 | PASS/FAIL矩阵 |
**完成标准：** 未批准不写入；重复提交不重复创建；已提交但响应丢失可回读；取消时不虚报成功。

## 13. 我的备注：金融测试、Agent Testing与智能测试平台
**测试经理智能助手：** 保持Vue3 iframe→Dify Chatflow→DeepSeek V4→Java Capability API→PostgreSQL的一期路线。执行统计和负责人查询继续只读；未来新增自动创建测试任务时，优先实现草案确认、服务端授权、幂等写入、取消/超时状态机和任务ID回读。无需为Wallet或Switchyard重构现有系统。

**日志脱敏检测平台：** 可参考Decisions API的批量判定形式，对现有500条脱敏样本做精筛质量对比；保持规则与AI状态独立、失败重扫/继续扫描的execution_epoch隔离，并对取消任务后的旧回调做拒绝处理。模型建议不能代替人工确认或同条件复扫。

**Agent Testing：** 增加Approval Binding Accuracy、Unauthorized Write Block Rate、Idempotency Pass Rate、Cancellation Consistency、Verified Task Success、Cost per Verified Task。**结论：真正的企业Agent成熟度取决于可信授权、可停止、可回读，而不是工具调用数量。**
