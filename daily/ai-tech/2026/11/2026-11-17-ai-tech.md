## 1. 今日摘要
1. **GitHub AI Scan批量启动（GitHub，11/16）**：公开预览可一次启动最多20个仓库的扫描，覆盖CodeQL未支持语言及补充漏洞检测；这是从配置到执行的新增能力。
2. **Copilot三款模型正式退役（GitHub，11/16）**：Claude Opus 4.8、Opus 5、GPT-5.6 Terra退出大多数入口，需按策略切换至推荐替代。
3. **Copilot VS Code 1.146（GitHub，11/16周报）**：实验性Agent模型对比工具、跨工作区会话Inbox、Copilot harness迁移提醒。
4. **Gemini App历史与训练控制（Google，11/16）**：聊天历史可保留同时选择不用于生成式AI训练；关闭History后新聊天仍可能为安全等目的保留约两个月，逐步全球推出。

**判断：** 模型版本、数据保留和安全扫描不再只是管理员配置，必须进入Agent持续测试和审计体系。

## 2. AI / 大模型 Top News
### 2.1 GitHub AI Scan支持批量启动最多20个仓库
**GitHub｜2026-11-16｜新颖度5/5｜Public Preview。**  
官方：https://github.blog/changelog/2026-11-16-bulk-start-ai-scan-for-repositories/  
AI Scan扫描仓库默认分支，结果汇入Code Scanning告警列表；组织管理员可在组织设置或告警页面对最多20仓库启动扫描，仓库级也可单独启动。支持github.com和具备数据驻留能力的GitHub Enterprise Cloud，不要求Copilot许可证。**区别于11月13日已报道的API配置开关：此次是批量触发执行。** 预览能力不等于支持隔离内网GHES，且AI扫描不能替代CodeQL、人工复核和真实安全测试。  
**实践：** 对多项目日志脱敏扫描设计“策略启用”与“任务触发”两个独立操作；批量任务需要独立状态和失败重试。

### 2.2 GitHub Copilot三款模型11月16日正式退役
**GitHub｜2026-11-16｜新颖度5/5｜实际生效。**  
官方：https://github.blog/changelog/2026-11-16-github-copilot-models-deprecated-on-november-16-2026/  
退役Claude Opus 4.8（推荐Opus 5.5）、Claude Opus 5（推荐Opus 5.5）、GPT-5.6 Terra（推荐GPT-6.1 Sol或GPT-6 Luna）。Opus 4.8对部分个人年付订阅者仍有例外；Opus 5仍可能用于已授权的拒绝回退，但已从模型选择器移除。企业默认启用策略和管理员禁用策略影响替代模型可用性。**区别于11月15日报道的12月14日六款模型未来退役公告。**  
**实践：** 模型ID盘点、失败回退、Golden Set回归和权限合规必须一起进行。

### 2.3 VS Code Copilot 1.146：Agent可调用实验性模型对比
**GitHub｜2026-11-16周报｜新颖度4/5｜实验功能。**  
官方：https://github.blog/changelog/2026-11-16-github-copilot-weekly-releases-november-9/  
开启Compare Models与Agent tools后，Agent可以查询可用模型、发起比较并读取结果；Agents窗口Inbox聚合跨工作区会话并优先显示需要人工处理的会话。官方还提示Local harness将在2027年2月移除，Copilot harness已是新会话默认。实验功能的评估结果不等于独立业务真值，必须用同一固定任务集验证。  
**实践：** 借鉴“模型对比结果+业务断言”和“待人工处理队列”，避免只以模型自评选择版本。

### 2.4 Gemini App新增历史记录与训练用途分离
**Google｜2026-11-16｜新颖度5/5｜逐步推出的隐私设置。**  
官方：https://blog.google/innovation-and-ai/products/gemini-app/updated-controls/  
Google宣布允许保留聊天历史，同时选择不将其用于生成式AI模型训练；仍可管理保留时长及删除历史。若关闭新History设置，未来聊天仍可能保留约两个月，用于响应、反馈和安全保护。此公告针对Gemini App，不可推断所有Gemini API/企业产品采用同一策略。  
**实践：** 企业准入表应分别记录“训练用途”“历史保存”“安全留存”“删除能力”，不能把不训练误解为零留存。

## 3. 科技行业动态
**3.1 AI开发平台开始治理Agent会话积压（11/16）。** VS Code的Inbox聚合跨工作区会话，优先处理需要人的任务；这说明多Agent协作中的人工审批和会话状态本身成为产品能力。来源：GitHub周报。  
**3.2 AI隐私控制趋向细粒度（11/16）。** Google将训练用途与历史保留分离，但关闭History仍存在约两个月的特定用途留存。企业采购不能只问“是否用于训练”，还要问留存、删除和数据处理区域。来源：Google官方。

## 5. Agent Ecosystem
**Agent / Workflow / 编排：** Agent Inbox提供会话待办队列的产品参考。工作流应区分WAITING_APPROVAL、RUNNING、SUCCEEDED、FAILED、UNKNOWN，超时不能自动标记成功。  
**Skill / MCP / Tool Calling：** Skill封装操作规范，MCP提供调用协议，但真实权限和业务结果由可信Java Capability API验证。工具调用失败重试须使用幂等键。  
**Browser Agent / 安全治理：** 批量AI Scan和模型版本切换都应输出可审计Trace；浏览器执行成功不等于真实业务完成。  
**本周最值得体验：** 在脱敏Mock工程上建立同一任务的两模型对比表，记录工具选择、业务断言、延迟和成本。  
**Agent 实践启发：** 让Agent比较模型可以提升效率，但最终发布门禁应来自确定性业务验证，而不是Agent自评。

## 9. 今日实战
在测试经理助手的Mock接口上建立“版本切换+业务结果回读”样本：
```json
{
  "trace_id": "mock-20261117-001",
  "capability_id": "query_execution_summary",
  "model_version": "candidate",
  "tool_status": "SUCCESS",
  "business_assertion": "PASS",
  "permission_assertion": "PASS",
  "verified_success": true
}
```
business_assertion与permission_assertion由可信验证器产生，不由模型自行声明。

## 10. Today Worth Thinking
如果Agent在升级模型后输出更流畅，但权限阻断或业务事实准确率下降，是否仍可发布？**不应仅看平均评分。** 金融关键场景的越权和错误写入必须设置硬门禁。

## 11. 30分钟 Action
- 0—10分钟：准备执行统计、负责人查询、越权查询、工具超时、空结果、重复调用六条脱敏Mock。
- 10—20分钟：执行当前模型/候选配置，记录Capability、工具参数、耗时和Trace。
- 20—30分钟：用Java Mock结果核对事实与权限，输出PASS/FAIL及差异表。

完成标准：六条都有证据；越权未放行；不因模型回答自然就跳过真实数据验证。

## 13. 我的备注
**金融测试经理助手：** 继续采用Vue3 iframe、Dify Chatflow、DeepSeek V4、Java Capability API、PostgreSQL。近期先完成内网联调和只读查询；模型路由未来扩展时需固定Golden Set、Schema、权限断言。  
**日志脱敏检测平台：** 借鉴批量扫描的配置/执行分离；继续扫描、失败重扫应按server与执行轮次隔离，聚合结果只依据当前有效轮次；500条样本用于AI精筛版本回归。  
**Agent Testing：** 建议跟踪模型退役影响、权限阻断率、工具参数准确率、真实业务回读率、扫描覆盖率、每有效任务成本。  
**今日结论：** 企业Agent的长期稳定性来自可替换模型、可审计工具执行和可信业务验收。
