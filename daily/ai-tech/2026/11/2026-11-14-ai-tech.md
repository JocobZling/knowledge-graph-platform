## 1. 今日摘要
今日最值得关注的是GitHub将AI Scan仓库级开关纳入REST API，支持组织和仓库分级治理；Google DeepMind公布AlphaProof Code，利用多Agent生成Lean证明并由确定性验证器检查；GitHub提供可跨客户端复用的Skill工程实践；Secret Scanning新增Cloudflare服务令牌检测。四者共同指向：**AI可以发现和建议，但权限与最终验证必须由可信机制完成。**

## 2. AI / 大模型 Top News

### 2.1 GitHub AI Scan仓库级REST API（11月13日，新颖度5/5）
GitHub发布公开预览：在组织和仓库级AI Scan配置接口中增加`repository_scan`字段，允许`enabled/disabled`。组织策略限制下仓库不能自行突破；企业策略不允许时启用请求返回422。批量更新`pr_scan`与`repository_scan`时，如果一项被拒，整次请求均失败。**开启开关不会立即扫描**，仍需有写权限者按需触发，扫描消耗AI credits。GitHub Enterprise Server暂不支持。  
来源：https://github.blog/changelog/2026-11-13-manage-ai-scan-for-repositories-using-the-rest-api/  
**实践价值**：将AI安全扫描配置纳入策略即代码；用模拟422验证原子性与策略继承。

### 2.2 AlphaProof Code形式化验证Signal核心加密实现（11月10日，新颖度5/5）
Google DeepMind介绍多LLM Agent框架：专家审阅安全规格，Agent生成Lean证明，由Lean独立检查。官方称生成超过600万行Lean证明代码、用时约四周，并在隔离旧版本中重新引入两个已修复缺陷，均能识别不安全。**这不是对整个Signal应用或所有安全属性的完整无漏洞证明**；证明范围由审阅的规格限定。  
来源：https://deepmind.google/blog/introducing-alphaproof-code/  
**实践价值**：金融核心接口可先用属性测试、契约测试、确定性断言建立独立验证，再考虑高成本形式化方法。

### 2.3 GitHub发布跨Agent复用Skill实践指南（11月12日，新颖度4/5）
GitHub提出以版本化目录和`SKILL.md`沉淀可复用操作规范，以项目manifest承载业务配置，以打包脚本适配不同Agent客户端。文章强调Skill只提供操作说明，不能授予数据库权限；独立Proof Agent可对代码变更给出证据，但示例静态审查**不执行测试**。  
来源：https://github.blog/ai-and-ml/github-copilot/build-once-run-on-any-agent-a-practical-guide-to-agent-skills/  
**实践价值**：将测试经理助手的查询规范、AI代码审阅清单和日志复扫标准沉淀为Skill，执行权限仍留在Java服务端。

### 2.4 Secret Scanning新增Cloudflare服务令牌检测（11月12日，新颖度3/5）
GitHub Secret Scanning新增`cloudflare_access_service_token`类型；Partner类型在公开仓库检测后可能向发行方报告，User类型按仓库和配置生成告警。属于检测规则覆盖更新，不是通用AI模型升级。  
来源：https://github.blog/changelog/2026-11-12-secret-scanning-adds-a-detector-for-cloudflare/  
**实践价值**：敏感信息检测规则应有版本台账，新增类型须测试误报、漏报、历史数据补扫策略。

## 5. Agent Ecosystem
### 5.1 Skill与MCP的职责边界
Skill是版本化操作规范；MCP是工具交互协议；Capability API承载业务语义和可信授权。跨客户端复用Skill时，应检查工具可用性、凭据权限和输出证据，而不是假定`SKILL.md`可直接执行。

### 5.2 Workflow与安全治理
AI Scan配置API展示了“组织策略优先、仓库可选退出、冲突原子拒绝”的模式。对测试经理助手写操作，应采用相同的多级授权思想：用户权限、Agent权限、业务对象范围三者取交集。

### 5.3 Browser Agent与独立验证
浏览器点击、工具成功返回和Agent文字自评都不代表业务成功。查询需核对可信数据；写操作需回读记录；代码审阅需执行真实测试，不能只靠静态Proof Agent。

**本周最值得体验**：为一个Mock查询Skill制作`SKILL.md`和`manifest.json`，在两种客户端中测试参数与权限一致性。  
**Agent 实践启发**：将“建议者、执行者、验证者”解耦，并使关键验证器不依赖生成模型的自我评价。

## 7. 企业实践
**Google DeepMind与Signal协议实现验证**：研究人员审阅形式化安全目标，Agent承担大规模证明搜索与生成，Lean负责机械检查；并通过重新引入历史缺陷验证方法的区分能力。官方报告四周完成目标范围内的验证，未披露普适成本或覆盖整个Signal应用的结论。可借鉴“人定规格—Agent生成—机器验证—回归反证”链路。来源：https://deepmind.google/blog/introducing-alphaproof-code/

## 8. 今日工具推荐
**Lean 4**：在Mock环境了解`theorem`、`by`及编译器对证明的验证方式。先学习可机检的结果契约思想，不要求团队现在投入形式化验证生产建设。

## 9. 今日实战
设计一个“测试任务创建”的双重验证契约：
```json
{
  "trace_id": "mock-20261114-001",
  "capability_id": "create_test_task",
  "policy_decision": "ALLOW",
  "agent_claim": "CREATED",
  "db_readback": "NOT_FOUND",
  "verified_success": false
}
```
以上为模拟数据。即使Agent称创建成功，只要可信回读找不到任务，系统必须返回未验证而不是成功。

## 10. Today Worth Thinking
**如果AI生成了完整的证明或审查报告，但没有独立验证器确认，能否作为金融核心系统的验收依据？**  
不能。需明确规格覆盖范围、可重复执行证据和失败路径；对无法形式化的业务规则仍需人工验收与测试。

## 11. 30分钟 Action
- 0—10分钟：创建一个`create_test_task` Mock Skill，写明输入、输出、禁止越权和审批门禁。
- 10—20分钟：准备正常、缺参、越权、重复请求、假成功五条样本。
- 20—30分钟：用Java Mock服务执行并回读，记录`trace_id`、`policy_decision`、`verified_success`。
**完成标准**：五条场景均有独立PASS/FAIL；越权及假成功不允许进入已完成状态。

## 13. 我的备注：金融测试、Agent Testing、智能测试平台
**测试经理智能助手**：继续以Vue3 iframe + Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL为主。优先在现有查询和任务创建能力上增加可信授权、结果回读和Golden Set；不因形式化验证新研究而贸然更换编排框架。可把重复的接口分析与审阅规范沉淀为Skill，但敏感Schema与权限不得进入外部仓库。  
**日志脱敏检测平台**：新增规则类型时记录规则版本与扫描范围；继续扫描/失败重扫应绑定执行轮次，避免旧回调覆盖；AI精筛只给建议，复扫与人工确认决定闭环状态。  
**Agent Testing**：建议追踪权限阻断率、参数Schema合规率、可信回读成功率、假成功拦截率和每有效任务成本。  
**今日结论**：**从“Agent能完成什么”转向“完成结果由谁证明、执行权限由谁约束”。**
