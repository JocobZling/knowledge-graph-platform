## 2. AI / 大模型 Top News

### 2.1 GHES 3.23 RC：隔离内网CPU运行AI密钥检测
**GitHub｜2026-11-20｜Release Candidate / AI功能Public Preview｜新颖度5/5**  
官方：https://github.blog/changelog/2026-11-20-github-enterprise-server-3-23-release-candidate/

GitHub公布GHES 3.23候选版本：若企业使用GitHub Secret Protection，可在GHES本地运行AI检测非结构化密钥，支持air-gapped环境。官方明确称自包含微调模型运行于设备CPU，不需要GPU、托管LLM或外网连接。**限制：** 该能力处于公开预览，依赖相应产品许可；并不说明所有GitHub AI功能或Copilot均能离线运行。金融测试价值：在受限内网评估CPU推理的部署、吞吐、误报和数据驻留。

### 2.2 GHES 3.23 RC：恶意包识别覆盖多语言
**GitHub｜2026-11-20｜RC｜新颖度4/5**  
官方同上。GitHub Advisory Database扩大已知恶意包覆盖，从npm扩展至PyPI、Maven、RubyGems、NuGet、Go、Rust、Composer，自动接收OpenSSF malicious-packages数据。对于Java Spring Boot / Maven工程，建议将依赖恶意包检测纳入AI生成代码的合并前门禁；不能以“模型生成成功”代替依赖安全检查。

### 2.3 GHES 3.23 RC：短期OAuth Token与依赖更新冷却期
**GitHub｜2026-11-20｜RC；OAuth部分Public Preview｜新颖度4/5**  
官方同上。新增8小时过期的OAuth access token及refresh token机制；现有OAuth应用可选启用，新建应用默认启用。启用前必须确保客户端支持refresh，否则会导致登录中断。Dependabot默认等待新依赖版本发布至少三天后再发版本更新PR，降低抢先引入问题版本的风险；这不是对恶意包的绝对防护。Agent的MCP工具和业务API也应测试凭据过期、刷新失败与撤销后的拒绝行为。

**第四条：** 未发现足够独立且可核验的高价值AI/模型技术发布，不以旧闻补齐。

## 5. Agent Ecosystem
**5.1 MCP / Tool Calling / 安全治理：** 将能力分为READ、WRITE、ADMIN、SECURITY_REPORT；授权由Java服务端判定，不依赖模型传入的role字段。权限服务异常时关键写操作fail closed。
**5.2 Skill / Workflow：** 每个Skill记录owner、版本、依赖清单、执行权限、网络需求、准入测试和回滚方式；Agent自动发现Skill时先通过策略过滤，再交给模型选择。
**5.3 Browser Agent / 运行环境：** 浏览器操作需要短期凭据、用户身份绑定、沙箱资源预算及可信回读。云沙箱和air-gapped CPU检测是不同产品形态，不能互相替代。

**本周最值得体验：** 在Mock环境模拟8小时Token到期后，Agent重复调用读取/写入工具的行为；无需等待真实8小时，可注入过期时间。
**Agent实践启发：** 工具是否可调用，应由可信身份、权限、凭据和业务状态共同决定，而不是由Prompt决定。

## 7. 企业实践
**GitHub：最小权限漏洞协作。** 11月20日GA的四项权限覆盖查看、管理、接受私密漏洞报告、发布安全公告/CVE申请；组织可只授权指定仓库，避免为了处理漏洞授予全仓库管理员权限。合并临时私有fork仍需管理员或安全经理，保密评论还受写权限约束。效果是更细粒度授权能力已上线，官方未披露量化风险下降数据。金融测试借鉴：安全扫描报告的查看、复核、关闭、发布与规则管理应拆分权限。官方：https://github.blog/changelog/2026-11-20-security-advisory-permissions-are-now-generally-available/

## 9. 今日实战
为测试经理助手定义权限测试矩阵：

| 场景 | 身份 | 动作 | 预期 |
|---|---|---|---|
| T01 | 测试人员 | 查询本人执行统计 | ALLOW |
| T02 | 测试人员 | 查询他人敏感明细 | DENY |
| T03 | 测试经理 | 创建测试任务 | 需授权/审批 |
| T04 | 任意用户 | 使用过期Token调用工具 | DENY并可控刷新 |
| T05 | 安全策略服务超时 | 高风险写操作 | DENY并记录Trace |

测试用例为Mock，最终权限由可信后端断言。

## 10. Today Worth Thinking
**如果一个MCP工具可以在内网运行，但其依赖包、身份令牌和更新渠道仍需要外网，它是否真正满足隔离部署？** 应分别核验运行期网络、构建期依赖、许可证、升级机制、遥测和密钥生命周期。

## 11. 30分钟 Action
0—10分钟：选取一个现有Java查询接口，列出读写权限与Token来源。  
10—20分钟：在Mock环境执行正常、越权、过期、刷新失败、策略超时五种情况。  
20—30分钟：记录每条Trace与服务端断言，形成一张Agent工具准入表。  
**完成标准：** 所有越权/过期/策略故障写操作均被阻断；允许操作有可信回读。

## 13. 我的备注：金融测试、Agent Testing、智能测试平台
**测试经理智能助手**：主工程保持Vue3 iframe + Dify + Java API + PG，优先把执行统计和负责人查询的身份/权限边界测清楚；探索工程把Capability Registry增加risk_level、network_policy、token_policy、dependency_review字段。暂不因GHES的AI密钥检测而更换编排架构。

**日志脱敏检测平台**：本地CPU模型的思路值得研究，但不能直接推断适用于当前500条AI精筛样本或现有服务器资源。建议对比规则扫描与本地模型的误报率、漏报率、耗时及资源占用，失败重扫仍按服务器和执行轮次隔离。

**Agent Testing**：新增Token到期拒绝率、权限故障阻断率、MCP依赖审查覆盖率、离线网络出口测试和可验证业务结果五项指标。

**结论：** Agent的可扩展性必须与可授权、可审计、可隔离和可回归同时建设。
