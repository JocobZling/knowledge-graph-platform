**北京时间：2026-11-22（星期日）**  
**今日主题：Agent Framework 供应链投毒：比模型越权更靠前的依赖安装风险。**

**时效与去重：** 读取2026-11-15至21七篇完整历史日报并检查11月目录（未发现独立主题索引）。优先核查11月21日至22日，未发现足够独立的高价值官方发布；扩展至11月17—20日。11月21日报道GHES恶意依赖检测能力，但未报道**真实的Microsoft Agent Framework PyPI恶意包事件**，故本期作为新安全事件独立收录。新颖度是编辑判断。拒绝使用旧新闻填满数量。

## 1. 今日摘要
**最重要的安全事件：** Microsoft Agent Framework 的PyPI包 `agent-framework` 在11月17日出现两个恶意版本1.26.1、1.26.2。GitHub Advisory 11月18日确认恶意代码利用Python `.pth` 启动钩子，即使应用没有导入Agent Framework，也会在Python启动时执行，试图窃取环境变量、云与CI凭据。两个版本已从PyPI下架；最后确认干净的版本为1.26.0。对已安装环境不能只做版本回退，须按凭据可能泄露处置。  
**本期不足四条独立AI新闻，严格减量。** 这不是11月21日GHES安全扫描产品公告的重复报道，而是具体受害依赖的安全事件。

## 2. AI / 大模型 Top News
### 2.1 Microsoft Agent Framework PyPI恶意版本事件
**主体：Microsoft Agent Framework / PyPI / 安全研究者｜恶意发布：11月17日；GitHub Advisory：11月18日｜新颖度5/5｜安全事件。**  
[GitHub Advisory GHSA-764m-3ppc-5m73](https://github.com/advisories/GHSA-764m-3ppc-5m73)；[Wiz原始分析](https://www.wiz.io/blog/malicious-version-of-microsofts-agent-framework-published-to-pypi)；[项目Issue](https://github.com/microsoft/agent-framework/issues/10411)。

- 受影响包为Python发行包 `agent-framework` 的**1.26.1和1.26.2**，不要泛化为所有Microsoft Agent Framework版本或.NET包。
- 1.26.1于11月17日20:35 UTC发布，1.26.2于21:08 UTC发布；两个恶意版本已从PyPI移除。
- `.pth` 文件可在Python解释器启动时执行恶意逻辑；正常应用功能仍可能工作，因此功能测试通过不代表环境安全。
- 恶意代码试图读取环境变量、开发凭据、云令牌和CI/CD身份材料；具体受害范围与发布权限被攻破的途径尚未完全确定。
- **行动：** 排查锁文件、SBOM、构建日志、pip/uv缓存及内网镜像；如确认安装过恶意版本，隔离重建环境、轮换可能接触的凭据并调查外联与CI日志。只执行 `pip install -U` 或退回1.26.0不足以完成事件处置。

## 3. 科技行业动态
**3.1 AI开发框架发行渠道成为攻击面（11月17—18日）。** 这次事件表明，风险可能发生在依赖安装与解释器启动阶段，早于模型推理、Tool Calling与MCP权限检查。企业Agent平台需同时治理构建身份、依赖来源、制品哈希与运行时网络出口。来源：Wiz、GitHub Advisory。  
**3.2 安全信息披露与企业响应存在时间差（11月18—21日）。** 恶意包虽被下架，但内部制品镜像和CI缓存仍可能保留文件；项目Issue明确提示不能依赖“最新版本”自动修复。对隔离内网应建立外部安全公告到内部依赖清单的离线同步与核查流程。来源：GitHub Issue #10411。

## 5. Agent Ecosystem
**5.1 Agent / Skill / MCP：** 在工具调用授权之前增加依赖准入。Skill、MCP Server和Agent Harness均应记录软件包名称、固定版本、来源、哈希、许可证、维护者与风险等级；对未知依赖默认拒绝进入受限环境。  
**5.2 Workflow / Tool Calling：** 将构建机、模型工作流和业务API的凭据分开，避免同一运行环境同时拥有模型密钥、数据库管理员凭据与CI发布令牌。对运行环境实施最小权限和出口限制。  
**5.3 Browser Agent / 安全治理：** 浏览器自动化沙箱、Python工具容器与CI Runner同样需要审查启动脚本和第三方依赖，不能只审计浏览器页面操作。  
**本周最值得体验：** 用虚构依赖清单执行一次恶意版本匹配检查，不安装真实恶意包。  
**Agent 实践启发：** 模型正确、工具授权正确、任务结果正确，仍不等于底层执行环境安全。

## 6. 开源推荐
**[ossf/malicious-packages](https://github.com/ossf/malicious-packages)**｜**643 Stars（2026-11-22 GitHub API快照）**｜**Apache-2.0**。OpenSSF维护的恶意软件包报告仓库，可用于研究供应链事件证据和版本匹配。**推荐理由：** 作为企业依赖准入数据源之一，适合离线同步安全记录、对照SBOM；不能单独替代漏洞扫描、来源证明和人工审查。成熟项目推荐，非今日首发。

## 7. 企业实践
**Wiz与开源安全社区的应急分析。** Wiz对恶意wheel和Python启动钩子进行分析，GitHub Advisory将受影响版本标准化登记，项目Issue提供排查与处置建议。可借鉴的流程是：**发现→固定受影响版本→确认传播渠道→查缓存/镜像→凭据轮换→重建与回归**。公开材料不足以给出企业统一受害数量或完整攻击归因，不能虚构量化成效。

## 8. 今日工具推荐
**pip-audit（[PyPA官方项目](https://github.com/pypa/pip-audit)）**：用于Python依赖已知漏洞审计。它不保证发现所有恶意包，特别是刚出现的投毒版本；须结合GHSA、OpenSSF恶意包数据、锁文件和构建记录。银行内网先使用批准的离线数据源与Mock工程。

## 9. 今日实战
准备虚构SBOM，包含 `agent-framework==1.26.1`、`agent-framework==1.26.0`、`example-lib==1.0.0` 三项。规则匹配 `agent-framework` 的1.26.1或1.26.2时返回BLOCK；对1.26.0只标记“不在本事件恶意版本清单”，**不能等同于整体安全**。输出匹配规则ID、版本、来源链接与待人工复核状态。不要安装恶意包。

## 10. Today Worth Thinking
**如果Agent框架运行正常、业务测试全部通过，但构建环境在安装依赖时已经泄露密钥，现有测试报告会不会错误地给出“上线通过”？** Agent Testing应将供应链完整性与运行时凭据安全列为独立发布门禁。

## 11. 30分钟 Action
- **0—10分钟：** 检查脱敏样例的requirements/lockfile，建立固定依赖清单。
