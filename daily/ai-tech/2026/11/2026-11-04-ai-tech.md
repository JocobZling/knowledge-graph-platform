# AI 与 Agent 每日简报 v2

**今日主题：Agent 的配置依赖开始像代码一样管理——锁定Skill、建模LLM数据流、隔离Coding Agent执行。**  
**时效窗口：优先2026-11-03至11-04早间；必要时扩展近7天。**

## 1. 今日摘要
**四个新变化：** ① GitHub Dependabot在11月3日支持Agent Package Manager（APM）声明的Skill、Prompt、Instructions的Git依赖版本更新，并可再生锁文件；② CodeQL 2.27.3引入可选的`ai`威胁模型，允许将LLM生成数据作为自定义不可信数据源进行流分析；③ Copilot进入JetBrains Air，通过ACP支持本地及隔离云端Coding Agent任务；④ GitHub REST API可按资源直接查询所属成本中心。**核心判断：** Agent的依赖供应链、运行时权限、数据流与成本归属应分层治理。

## 2. AI/大模型 Top News
### 2.1 Dependabot支持APM依赖版本更新
**GitHub｜2026-11-03｜新颖度5/5｜GA。** [官方公告](https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager)。Dependabot现在可以读取`apm.yml`中的受支持Git依赖，提出版本升级PR；存在`apm.lock.yaml`时重新生成锁文件。github.com所有计划可用，GHES 3.24计划支持。**重要边界：只支持版本更新，不支持APM安全更新。** 对金融内网：Skill/Prompt不应无审查自动升级；固定版本、审阅差异、运行Golden Set后再合并。
### 2.2 CodeQL 2.27.3增加LLM数据威胁模型
**GitHub｜2026-11-03｜新颖度5/5｜版本更新。** [官方公告](https://github.blog/changelog/2026-11-03-codeql-2-27-3-adds-python-3-15-features-and-json-data-extensions)。CLI增加JSON数据扩展语法和可选`ai` threat model；后者**没有内置source模型**，需自行用数据扩展声明来源。Python部分查询会根据配置的威胁模型考虑额外数据源。Java/Kotlin的SSRF与重定向查询改进对固定host白名单判断的识别，减少误报。对Dify/Java API：可研究“LLM输出→URL/路径/SQL参数”的污点传播，但不能认为开启选项即自动覆盖所有Prompt Injection。
### 2.3 GitHub Copilot接入JetBrains Air
**GitHub｜2026-11-03｜新颖度5/5｜产品集成。** [官方公告](https://github.blog/changelog/2026-11-03-github-copilot-is-now-available-in-jetbrains-air)。使用Agent Client Protocol（ACP），支持在IDE中发起、并行查看任务，亦可在Air Teams组织中运行云任务。云任务在新虚拟机的Docker容器中运行，流量经代理且任务间不继承状态。云端要求JetBrains Air Teams组织、Copilot订阅及管理员启用。Air目前不能为Copilot设定单独支出限额，Air分析也不包含Copilot使用量。**内网结论：不是离线方案；需单独评估出口与数据驻留。**
### 2.4 GitHub资源成本中心API
**GitHub｜2026-11-03｜新颖度4/5｜API发布。** [官方公告](https://github.blog/changelog/2026-11-03-look-up-a-resources-cost-center-with-the-github-rest-api)。可按用户、组织、仓库或企业团队查询成本中心ID和名称；无归属返回空`memberships`。访问权限按企业账单角色约束。对Agent平台的启发是将成本归属从“手工汇总”前移到任务资源标签；该API本身并非模型Token账单接口。

## 3. 科技行业动态
**3.1 Python 3.15依赖治理。** GitHub 11月3日宣布Dependabot支持Python 3.15，github.com可用，GHES 3.24计划包含。对Python Agent工具链可减少依赖升级盲区；与Java主项目没有直接迁移关系。[官方](https://github.blog/changelog/2026-11-03-dependabot-now-supports-python-3-15)。
**3.2 Agent配置进入可复现交付。** Microsoft APM官方文档说明`apm.yml`管理Skills、Prompts、Instructions和MCP声明，`apm.lock.yaml`锁定Git版本与内容哈希；策略可限制来源并阻止未明确批准的传递MCP依赖。这是供应链安装控制，不是运行时沙箱。[官方文档](https://microsoft.github.io/apm/concepts/what-is-apm/)。

## 5. Agent Ecosystem
**5.1 Skill供应链：** APM清单、内容哈希和Dependabot PR形成“声明—锁定—审查—回归”链路。它不等于自动安全审计，尤其要防范Prompt、Skill变更引入新的指令或工具范围。
**5.2 MCP/Tool Calling与安全：** APM管安装前的依赖和来源；Java Capability API管运行时身份、数据范围、写操作授权；CodeQL帮助识别不可信数据流。三者不能相互替代。
**5.3 Coding/Browser Agent与Workflow：** JetBrains Air的ACP和隔离云任务体现“协议连接+独立执行环境+审阅”模式。对Browser Agent也应保留会话隔离、独立业务断言与真实副作用回读。
**本周最值得体验：** 用本地假Skill清单模拟一次依赖升级，审查版本差异并跑六条Golden Set，不接真实银行系统。
**Agent实践启发：** “锁文件相同”只说明输入配置可复现，不说明模型输出一定确定；仍需Trace与业务断言。

## 9. 今日实战
为测试经理助手建立最小Skill登记表：`skill_id`、`source_repo`、`commit_sha`、`content_hash`、`allowed_tools`、`reviewer`、`golden_set_version`。升级时比较内容哈希、工具范围与回归结果；即使模型仍为DeepSeek V4，也能先落实供应链准入。

## 10. Today Worth Thinking
**Skill的版本和哈希都合法，但它把只读查询改成了写入工具调用，是否应允许发布？** 答案应由工具授权策略和Golden Set决定，而非仅凭安装完整性。

## 11. 30分钟 Action
**0—10分钟：** 选择一个脱敏Skill/Prompt，记录来源、版本、哈希和允许的工具；**10—20分钟：** 模拟修改Skill文本与工具声明，检查变更差异；**20—30分钟：** 执行6条Golden Set：合法查询、越权查询、未知工具、写入请求、伪造权限、旧版配置回滚。完成标准：每条PASS/FAIL、异常无真实副作用、记录审批人。

## 13. 我的备注
**测试经理智能助手：** 维持Vue3 iframe + Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL。先建立查询能力的Schema/权限/Golden Set；不因APM出现而更换框架。若未来引入Skill或MCP，增加清单锁定与审批。
**日志脱敏检测平台：** AI精筛的Prompt/规则版本应随扫描轮次记录，避免模型/规则变更后无法复现；继续扫描与失败重扫仍要隔离`execution_epoch`，阻止旧回调覆盖新状态。
**Agent Testing：** 建议跟踪`Skill Provenance Coverage`、`Tool Authorization Accuracy`、`Prompt Regression Pass Rate`、`Claim–Effect Consistency`。**结论：** Agent配置可以像代码一样版本化，但业务授权和真实执行结果仍需独立验证。
