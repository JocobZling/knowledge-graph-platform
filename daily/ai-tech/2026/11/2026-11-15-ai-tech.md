## 2. AI / 大模型 Top News

### 2.1 Gemini 4 Hydrogen 在 GitHub Copilot 正式可用
**主体：GitHub/Google｜发布时间：2026-11-13｜新颖度5/5｜Copilot平台GA，非原厂模型首发。**  
官方：https://github.blog/changelog/2026-11-13-gemini-4-hydrogen-in-github-copilot/

GitHub将其定位为速度优先的Flash模型，适合Agent编码、工具使用和多步骤工作流，称其指令遵循优于Gemini 3.8 Flash。覆盖VS Code、Visual Studio、Copilot CLI、coding agent、Copilot app、JetBrains、Xcode、Eclipse、SDK等入口，面向Pro/Pro+/Max/Business/Enterprise逐步开放；企业管理员可通过模型策略控制。采用基于用量的供应商标价计费。**没有可独立核验的金融Java项目胜率，不宣称普遍优于其他模型。**

**实践价值：** 为同一组脱敏Java任务比较轻量模型和复杂推理模型的“每有效任务成本”，而非只比较Token单价。

### 2.2 GitHub Enterprise Server 支持在 Copilot app 中 GA
**主体：GitHub｜发布时间：2026-11-13｜新颖度5/5｜从预览转GA。**  
官方：https://github.blog/changelog/2026-11-13-github-enterprise-server-support-in-the-github-copilot-app/

Copilot app 1.2.0及以上可添加GHES账户，操作远程仓库、Issue和PR；必须先登录GitHub.com或GHE.com账户，且**GHES云会话不可用**。这提升了混合企业代码仓库的工作流可达性，但并不证明模型推理、身份认证或数据流可在完全隔离内网运行。

**实践价值：** 金融企业先核查身份流、网络出口、仓库权限、日志留存和是否允许外部账户，再判断可用性。

### 2.3 Copilot 公布12月14日模型退役清单
**主体：GitHub｜公告2026-11-13｜计划生效2026-12-14｜新颖度5/5｜生命周期公告。**  
官方：https://github.blog/changelog/2026-11-13-upcoming-deprecation-of-selected-github-copilot-models-in-december/

退役包括 Claude Fable 5、Claude Haiku 4.5（个人年付用户例外）、Gemini 3.8 Flash、Gemini 4 Argon、Grok 4.6、Kimi K3；建议替代依次为 Fable 5.2、Haiku 5.5、Gemini 4 Hydrogen、Gemini 4 Carbon、Grok 4.7，Kimi K3替代待公告。涉及Copilot Chat、编辑、Agent和补全。企业默认模型策略可能自动开放替代模型，若关闭全局默认或明确禁用则需管理员处理。

**实践价值：** 对Agent工作流进行模型ID盘点、替代模型合规审查和Golden Set回归，避免“模型突然不可用”导致任务失败。

**第四条：** 无符合时效、去重与重要性要求的独立高价值公告，按质量规则留空，不补旧闻。

## 5. Agent Ecosystem

### 5.1 Agent与Workflow：路由应按任务而非模型热度
为执行统计、负责人查询、代码修改分别建立质量门禁。轻量模型仅在权限、参数、业务事实均达标时承接任务；复杂任务可升级，但不能自动突破预算和数据范围。

### 5.2 Skill、MCP与Tool Calling：统一契约不随模型变更
Skill定义业务操作规范，MCP或Java API提供受控工具，服务端检查身份、Schema、幂等和副作用。模型退役时应替换推理组件，不应重写业务权限逻辑。

### 5.3 Browser Agent与安全治理：仓库访问不是模型数据合规
区分本地操作、远程仓库读取、云端推理和云会话；对每条链路明确日志、留存、审批及回读机制。

**本周最值得体验：** 用同一组6条Mock任务比较“默认模型”和“候选替代模型”的工具选择、错误处理和真实回读，记录每有效任务成本。  
**Agent 实践启发：** 模型升级/退役应触发回归与安全复核，而非仅修改模型名称。

## 8. 今日工具推荐

**MCP Inspector**：使用虚构工具 query_execution_summary 与 query_system_owner 测试参数必填、错误码和权限边界。它适合做协议层验证；最终业务结果仍需Java可信接口核验。

## 9. 今日实战

**模型替换兼容性契约（Mock）：**

```json
{
  "workflow_id": "test_manager_assistant",
  "capability_id": "query_execution_summary",
  "model_route": "candidate",
  "expected_tool": "query_execution_summary",
  "auth_decision": "ALLOW",
  "readback_verified": true,
  "regression_status": "PASS"
}
```

模型输出不可自行设置auth_decision或readback_verified，这两个字段必须由可信服务生成。替换模型后验证工具名、参数Schema、越权拦截、返回格式和超时降级。

## 10. Today Worth Thinking

如果模型A比模型B快40%，但每100次任务多出现一次错误工具选择，是否仍值得切换？对于金融写操作，关键错误可能直接否决速度优势；应先定义硬门禁，再比较平均性能。

## 11. 30分钟 Action

0—10分钟：列出2个只读Capability和1个写操作草案的模型依赖点；10—20分钟：准备正常、缺参、越权、空结果、超时、重复写入6条Mock；20—30分钟：对照旧模型基线运行并记录PASS/FAIL、耗时、工具调用次数。**完成标准：任何越权或假成功均阻断发布。**

## 13. 我的备注：金融测试、Agent Testing与智能测试平台

**测试经理智能助手：** 继续保持Vue3 iframe、Dify Chatflow、DeepSeek V4、Java Capability API、PostgreSQL架构。先把执行统计和负责人查询做成不依赖具体模型的Capability契约，补齐Golden Set、Trace和模型切换回归。无需因Copilot模型更新迁移架构。

**日志脱敏检测平台：** 模型替换可能改变误报/漏报分布；使用固定500条脱敏样本复测，并记录Prompt版本、模型版本、规则版本和执行轮次。失败重扫和继续扫描仍由确定性状态机负责。

**Agent Testing：** 优先测模型切换成功率、工具Schema合规率、越权阻断率、可信结果回读率、每有效任务成本。**结论：模型是可替换组件，业务能力与验证机制才是稳定资产。**
