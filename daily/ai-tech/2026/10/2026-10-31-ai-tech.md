## 2. AI / 大模型 Top News（4条）

### 2.1 Cursor扩展市场遭恶意包投放：插件准入成为紧急安全项
**事件/公告：2026-10-29｜重要程度：高｜新颖度：5/5**  
**官方来源：** [Cursor安全通告](https://cursor.com/blog/claude-code-extension-security-notice)

Cursor确认，其VS Code扩展市场在10月29日约02:27—13:35（美国太平洋时间）提供过恶意修改的Anthropic.claude-code扩展。最新官方通告列出受影响版本**2.1.312与2.1.313**，涉及Windows/macOS；恶意版本并非Anthropic制作或发布。Cursor表示已移除相关版本、重建市场并采取阻断措施。恶意代码试图收集主机信息、安装SSH后门和持久化机制；其部分步骤在普通权限下可能失败，但不能据此排除感染。早期公告只提到2.1.313，后续扩大至2.1.312，故以最新官方说明为准。

**重要边界：** Cursor初始披露的潜在影响规模为最多约5,000名用户，并非确认5,000台主机均被完全入侵。不能据此认定Anthropic官方扩展渠道遭入侵。**处置建议：** 如曾在指定时段从Cursor扩展市场安装上述版本，按官方通告核验端点、隔离异常设备、清理持久化、从可信设备轮换相关凭据；只升级/卸载扩展不足以完成处置。

**Agent Testing启发：** 将扩展来源、发布者、版本、包哈希、审批单和终端权限纳入Agent开发工具准入清单。特别关注本地SSH、网络出口、敏感目录读写和自动更新链路。

### 2.2 GTIG：攻击性Agent框架已经出现在真实入侵活动中
**发布时间：2026-10-30｜重要程度：高｜新颖度：5/5**  
**官方来源：** [Google Cloud / GTIG威胁情报](https://cloud.google.com/blog/topics/threat-intelligence/artex-and-friends-enter-agentic-offensive-frameworks)

Google Threat Intelligence Group与Mandiant表示，自2026年8月下旬起，在实际事件响应中观察到威胁行为者使用多Agent攻击框架，覆盖侦察、横向活动等多个环节。核心变化并非出现全新攻击原理，而是现有技术被Agent编排加速、规模化执行。官方强调控制面隔离、短期凭据、最小权限、网络分段和行为检测等既有防护原则。

**事实边界：** 这属于真实事件观察与威胁情报，并非“所有Agent都能自主入侵”的能力证明。也不应把开源安全测试框架一概认定为恶意。

**金融测试价值：** 需要测试同一Agent在多工具链上的权限累积，尤其是“读日志→获得敏感字段→调用外部工具”是否可能突破数据域；防御验证应关注跨步骤行为，而不是仅逐条审查Prompt。

### 2.3 AWS GovCloud：Codex与ChatGPT桌面应用的受控模型推理示例
**发布时间：2026-10-30｜重要程度：高｜新颖度：5/5**  
**官方来源：** [AWS配置指南](https://aws.amazon.com/blogs/machine-learning/configure-the-chatgpt-desktop-app-with-amazon-bedrock-in-aws-govcloud-us/)

AWS介绍在AWS GovCloud (US-West)通过Amazon Bedrock Mantle的Responses API路由模型推理，结合IAM、命名AWS凭据配置、受管设备策略、允许的模型端点与网络限制，供安全团队验证。文章涉及ChatGPT桌面应用中的Work与Codex使用模式，亦提及零数据留存选项和按Token计费。

**关键限制：** GovCloud区域数据驻留、IAM与网络约束**不等于无外网离线部署**；配置指南也明确不自动代表业务系统通过安全授权。且在该API模式下，ChatGPT工作区角色规则并不自动替代AWS IAM/设备策略，组织需独立审查端点、凭据、代码仓库与数据流。

**内网建议：** 将其作为“模型出口集中治理”的设计参考，不据此承诺银行内网可直接使用ChatGPT/Codex。现阶段仍以已批准的DeepSeek V4/Dify通道为主。

### 2.4 OpenAI支持robots.txt通用AI训练偏好信号
**发布时间：2026-10-30｜重要程度：中高｜新颖度：4/5**  
**官方来源：** [OpenAI公告（中文）](https://openai.com/zh-Hans-CN/index/helping-websites-express-ai-training-preferences/)

OpenAI宣布将尊重robots.txt中跨供应商共用的AI基础模型训练偏好信号，减少站点对多个独立爬虫规则的维护成本。公告提到IETF相关标准化工作，并表示将在**未来数月**实施、随后公布细节；现有robots.txt爬虫控制机制继续有效。

**注意：** 训练偏好信号并非实时授权API，也不能自动替代版权、数据分类、业务合同或个人信息保护规则。对企业知识库建设，建议在入库时记录来源、许可、可用于检索与可用于训练的不同用途标记。

## 5. Agent Ecosystem（3条）

### 5.1 Agent / Skill：开发工具插件是独立供应链
本次Cursor事件说明“官方名字”不能替代包来源与完整性验证。对IDE插件、Skill、MCP Server分别建立：来源白名单→版本/哈希→能力审查→沙箱试运行→审计→撤销。自动更新不能跳过受控发布流程。

### 5.2 MCP / Tool Calling / Workflow：身份权限需要随任务变化
10月30日[AWS与Saviynt的治理实践](https://aws.amazon.com/blogs/apn/governing-ai-agent-identity-with-amazon-bedrock-agentcore-and-saviynt-zuma/)强调Agent登记、责任人、可调用工具、动态授权和生命周期审查。对Java Capability API，推荐以真实登录用户和服务身份交集确定权限；工具描述、Skill提示词、模型置信度均不能扩权。执行时保存policy_version、tool_version、trace_id和审批参数快照。

### 5.3 Browser Agent / 安全治理：轨迹可读，不等于断言可信
Epsilon案例说明自然语言步骤可以减少页面选择器维护，但需要在关键点由确定性API或数据库回读验证。截图与轨迹证明“做过什么”，不必然证明“业务状态正确”；对跨租户会话还需验证数据与浏览器上下文隔离。

**本周最值得体验：** 使用假数据页面写3条自然语言UI意图测试（展示统计、权限拒绝、页面收起后恢复），同时保留3条Playwright/接口确定性断言，比较结果一致性与证据质量。  
**Agent实践启发：** 将软件包可信、工具执行合法、最终业务正确分成三个独立验收门禁。

## 7. 企业实践

### Worldwide Express：多Agent处理财务账单异常
**案例发布时间：2026-10-30｜[AWS官方案例](https://aws.amazon.com/blogs/machine-learning/how-worldwide-express-automated-freight-exceptions-with-amazon-bedrock/)**

Worldwide Express将多Agent异常处理嵌入既有运输管理系统，结合承运商知识和人工审批。企业披露上线六个月后，待处理异常规模由约1500万美元降至约400万美元（约75%）、回款周期改善四周、释放约1000万美元现金流，并声称年节约超过100万美元。**这些是企业个案自述，不是独立审计的普遍收益。**

**可借鉴点：** 先选高频、规则清晰、可回读的异常类型；Agent负责收集证据与生成处理建议，真实账务变更仍走既有授权/审批系统。对银行测试经理助手，优先“查询+解释+证据”，不急于实现自动写入。

## 9. 今日实战（1条）

## 13. 我的备注：金融测试、Agent Testing与智能测试平台

### 测试经理智能助手
一期继续采用**独立Vue3 iframe + Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL**。本期不建议为了外部云端Agent发布改变技术路线。增加工具/Skill注册清单、来源审批、API权限和调用审计即可。执行统计和负责人查询仍应由Java查询服务返回可信事实，模型不直接操作生产库。

### 日志脱敏检测平台
规则扫描与AI精筛应在隔离环境中处理日志上下文；敏感字段不要进入未经审批的外部Agent或插件。继续扫描、失败重扫保持execution_epoch与event_id幂等校验；日志内容视为不可信数据，不得驱动额外的系统命令或外部访问。

### Agent Testing建议指标
| 指标 | 检查内容 |
|---|---|
| Plugin Provenance Coverage | 插件来源、版本、哈希与审批是否完整 |
| Tool Permission Integrity | MCP/Skill实际权限是否被服务端约束 |
| Browser Evidence Completeness | UI动作、截图、断言与回读是否关联 |
| Verified Task Success | 业务事实正确且可独立验证 |
| Incident Remediation Closure | 卸载/升级之外的持久化与凭据风险是否复核 |
| Cost per Verified Task | 成功任务的总资源成本与复核成本 |

**今日结论：** Agent可以替人执行更多步骤，但必须证明“工具可信、路径合法、结果可验证”。
