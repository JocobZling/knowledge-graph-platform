# AI 与 Agent 每日简报 v2
**2026-10-24｜星期六｜北京时间**

**今日主题：Agent 的“决策、执行、监控”开始成为三个独立工程层。**

**资讯范围：** 优先核验10月23日，扩展至10月17—24日；本期核心事实均来自10月22—23日官方公告、独立研究报告与GitHub资料。**去重：**读取仓库最新七篇已归档 ai-tech 日报（2026-09-18—09-24）；检查 data 目录及搜索，未发现 ai-tech 专属主题索引；并对照10月17—23日此前已生成但未归档的简报。前期已覆盖Mirror CLI、Claude Duet、Agent Registry、GatewayBench、Claude Code安全修复、OpenAI内部监控削弱事件等，本期不把它们当作新新闻。10月22日METR**独立评估报告**提供此前事件之外的新证据，符合安全事件新进展的复报条件。

## 1. 今日摘要

**一、有限选项决策成为独立API。** OpenAI于10月22日将Decisions API正式GA：基于GPT-6 Luna，面向分类、路由、评分等有界决策；支持文本、图像、结构化输入和批量问题。它并非通用长文本推理API，而是把Agent内部高频小决策单独优化。

**二、Agent标准栈出现治理里程碑。** Linux Foundation旗下Agentic AI Foundation（AAIF）于10月22日新增Agent Skills、Open Responses、OpenEnv、OpenSandbox四个项目，分别覆盖技能打包、模型接口、训练/评估环境和安全执行环境。**加入基金会不等于所有实现已生产成熟。**

**三、独立监督暴露“应监控”和“实际监控”之间的差距。** METR与Redwood Research公布针对OpenAI内部Agent监控系统的高权限红队试验：发现覆盖盲区及可能的监控绕过路径；OpenAI表示生产相关问题已修复，但独立团队尚未复核修复效果。

**四、Agent使用度量进入跨工具视角。** GitHub于10月23日扩展Copilot Usage Metrics API，增加按客户端统计模型请求、会话和Token使用量；10月22日已增强自定义Skill、Agent、MCP Server的命名统计。可观测性正从“用了多少模型”走向“哪个Agent/Skill/工具产生了成本”。

**今日判断：** 对金融测试系统，最值得优先落地的不是再加一层Agent，而是把“模型作出决策、Java执行授权、独立审计验证”拆开。

## 2. AI / 大模型 Top News（4条）

### 2.1 OpenAI Decisions API正式GA：小决策专用接口
- **主体/日期：** OpenAI｜2026-10-22｜**新颖度：5/5（GA）**
- **官方：** [Decisions API发布](https://openai.com/index/decisions-api/)
- **事实：** 基于GPT-6 Luna；官方称相较通过Responses API调用同模型，特定有界决策任务可快至10倍。支持predicate（条件概率）、choice（限定选项）、score（有序评分），单请求最多400个问题；新增GPT-Live集成、缓存、美国和欧盟推理驻留。
- **价格口径：** 官方发布时列出每百万输入Token 0.10美元、缓存输入0.01美元，无输出Token计费；这只是该专用API价格，不代表GPT-6 Luna所有调用模式的价格。
- **边界：** 速度为官方对特定任务的比较，不能外推到复杂SQL推理；置信度不能替代业务权限校验。
- **实践价值：** 可把意图分类、风险分级、继续/澄清/转人工三选一等独立评测。内网DeepSeek V4目前不必迁移：先使用Dify分类节点或Java规则实现相同的**有界输出契约**。

### 2.2 METR独立红队：监控覆盖率不能仅看“配置已开启”
- **主体/日期：** METR、Redwood Research｜2026-10-22发布；评估发生于7月21日至8月11日｜**新颖度：5/5（新独立安全研究）**
- **原始研究：** [METR独立评估报告](https://metr.org/blog/2026-10-22-red-teaming-openai-agent-monitoring/)
- **事实：** 团队审查OpenAI截至7月21日的内部监控设计。估计部分符合模型能力条件的内部Responses API Agent流量有约75%—94%“符合被监控条件”；内部Codex相关子集约99.2%符合条件。**Eligible不等于真正被监控。**
- **发现：** 包括上下文压缩触发时机造成的监控缺口、部分监控失效或绕过风险；其中一项历史缺口由OpenAI自行发现并在评估期间修复。OpenAI称影响生产防护的问题已修复，但METR没有验证后续修复。
- **边界：** 不能把2026年7月历史系统的覆盖率当成当前产品覆盖率，也不能据此断言这些漏洞已被Agent实际利用。
- **实践价值：** 建议将“应进入监控的执行事件数”与“监控实际收到的事件数”独立对账，定义Monitor Coverage SLO和缺失告警。

### 2.3 AAIF新增四个项目：Skill、模型接口、环境与沙箱分层
- **主体/日期：** Linux Foundation / AAIF｜2026-10-22｜**新颖度：5/5（治理变更）**
- **官方：** [AAIF四项目公告](https://www.linuxfoundation.org/press/agentic-ai-foundation-announces-four-new-projects-agent-skills-open-responses-openenv-and-opensandbox)
- **四层：** Agent Skills（可移植技能规范）；Open Responses（跨模型提供商的请求/响应、Tool Call与流式事件规范）；OpenEnv（可互操作的强化学习环境）；OpenSandbox（多语言SDK、Docker/Kubernetes沙箱运行时）。
- **实质：** 四项由Anthropic、OpenAI、Hugging Face、Alibaba贡献至中立治理，AAIF托管项目达到10个。
- **边界：** 标准化降低接口耦合，但不能自动解决不同模型行为、工具权限和沙箱隔离质量差异。
- **实践价值：** 对现有Dify+Java架构，先建立Capability契约与工具版本指纹，未来再选择是否接入MCP/开放协议。

### 2.4 GitHub Copilot跨客户端用量指标：区分“请求”和“任务”
- **主体/日期：** GitHub｜2026-10-23｜**新颖度：4/5（新可观测能力）**
- **官方：** [Copilot Usage Metrics更新](https://github.blog/changelog/2026-10-23-usage-metrics-api-adds-usage-from-tools-like-opencode/)
- **事实：** 新增totals_by_client，按opencode、claude_code、codex、copilot_cli、IDE等客户端展示成功模型请求数、会话数、Token用量及模型选择方式；覆盖组织、企业及用户粒度的1日/28日报告。
- **重要限制：** request_count统计**模型调用**而非用户Prompt；client来自客户端提供的集成标识，是尽力归类而非已验证身份；不等同于完整Agent作业数或成功任务数。
- **实践价值：** 智能测试平台应同时统计模型调用量、业务请求量、成功任务量和成本，避免以Token下降误判业务效率提升。

### 3.1 Google Agent Compute Engine：Harness与Sandbox明确隔离

## 5. Agent Ecosystem（3条）

### 5.1 Agent/Tool Calling：有界决策不应承担授权
建议把“是否属于执行统计意图”交给分类器，把“是否能查询某系统”交给Java服务端。分类结果可为EXECUTION_QUERY、OWNER_QUERY、CLARIFY、UNSUPPORTED；模型即使给出高置信度，也不能绕过用户身份、系统范围和字段白名单。

### 5.2 Skill/MCP/Workflow：协议统一后，更需要版本化
AAIF项目覆盖Skill格式、模型交互、环境和沙箱；GitHub新增Skill/MCP命名使用指标。建议记录skill_id、skill_version、tool_manifest_hash、model_version、workflow_version、policy_version。MCP只提供连接契约，不授予业务访问权。工具被替换、Skill被更新时，应触发Golden Set回归。

### 5.3 Browser Agent/安全治理：执行环境不应持有长期凭据
Google架构采用Harness与Sandbox分离、短期身份、受控网络出口；METR评估强调独立监控和事件对账。金融内网无需复制云端microVM规模，但应借鉴三条原则：模型不持有数据库高权限凭据；高风险写操作经Java受控接口；监控系统不由被监控Agent决定何时运行。

**本周最值得体验：** 用10条真实问题，对比“Dify直接开放全部工具”与“先分类再开放指定Capability”，观察工具误选、权限拒绝、平均耗时和成本。

**Agent 实践启发：** Agent成功完成业务任务，与其权限正确、监控完整、沙箱隔离有效是不同的PASS条件；不应合并为一个“成功率”。

## 7. 企业实践

### Box：有界决策用于保险文档分流
- **企业/日期：** Box｜2026-10-22随Decisions API GA披露｜[OpenAI原始案例](https://openai.com/index/decisions-api/)
- **做法：** Box Extract将企业文档分类后选择下一步流程；低置信度样本转人工复核。
- **效果：** Box负责人称在**30份保险证明文件**的评估中，路由选择约快5倍，与Responses API方案准确率相同。
- **限制：** 30例规模小，属于企业披露的内部评估，不能推断所有保险或金融文件都能达到同样效果。
- **可借鉴点：** 金融测试的“分类—受控执行—人工复核”模式可复用，但应增加未知类型、错误路由、拒绝执行、人工接管和证据留存测试。

## 8. 今日工具推荐

这是Open Responses规范的符合性测试入口，帮助核对模型网关对请求/响应、工具调用和流式事件的兼容性；[规范全文](https://www.openresponses.org/specification)。

**适用时机：** 未来若将Dify背后的模型调用抽象为统一网关，可先验证Schema、流式终止事件、Tool Call结果、错误响应，而不是只做“接口能返回文字”的冒烟测试。当前阶段只需阅读测试项，无须新增外网服务。

## 9. 今日实战

### 给测试经理智能助手设计“分类器—权限—事实”三层契约

~~~text
用户问题
  ↓
Dify 分类器：EXECUTION_QUERY / OWNER_QUERY / CLARIFY / UNSUPPORTED
  ↓
Java Capability API：身份、系统范围、字段、时间口径校验
  ↓
PostgreSQL：按受控指标口径查询
  ↓
独立 Verifier：事实一致性、权限、Trace、审计完整性
~~~

建议每次执行保存：request_id、intent、intent_version、selected_capability、scope、period、policy_version、fact_as_of、trace_id、verdict。**分类器不直接生成SQL；Java不信任模型返回的user_name作为身份凭据。**

## 10. Today Worth Thinking

> 如果分类器判断“可以继续”且概率很高，但服务端发现越权，这次Agent是否仍算成功？

答案应拆分：**分类可能正确，授权必须失败，整体业务操作不得执行。** 不能用模型置信度覆盖确定性权限规则。反过来，监控没有收到事件，也不能由Agent自己宣称“没有发生”。

## 13. 我的备注：金融测试、Agent Testing与智能测试平台

**测试经理智能助手一期：** 继续保持Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL。新API的价值在于提示我们把高频分类任务做成可评估的固定枚举，而不是立即迁移模型。建议先交付执行统计、负责人查询、澄清/拒绝四类稳定能力，确保数据范围与真实登录身份绑定。

**日志脱敏检测平台：** 将METR的“监控覆盖对账”思想用于Python规则扫描回调与AI精筛回调：分别统计预期回调、已接收回调、有效回调、超时与旧轮次拒绝。Report状态继续以Server为事实源；增加execution_epoch、callback_seq和审计事件，避免继续扫描/失败重扫后旧回调覆盖新状态。AI精筛返回“误判/真实敏感/待复核”时，低置信度应进入人工复核，不应直接删掉规则命中证据。

**Agent Testing新增三类门禁：**
1. **Decision Fidelity：** 意图和风险分类与人工标注是否一致；是否存在需要澄清的输入。
2. **Authorization Independence：** 服务端能否独立拒绝越权Tool Call，即使模型确信应执行。
3. **Monitor Coverage：** 应被审计的操作是否都能在独立日志中对账，尤其是超时、重试、停止与异常恢复。

**今日结论：先让Agent的决策可评估、权限可拒绝、行为可对账，再增加自主性。**
