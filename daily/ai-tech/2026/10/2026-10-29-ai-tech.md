### 2.1 Gemini 4 Carbon：网络安全与长任务能力上台阶

**主体：Google DeepMind｜发布时间：2026-10-28｜新颖度：5/5｜状态：分阶段有限开放。**

Google称 Carbon 在 Artificial Analysis Intelligence Index v5.0 得分59，SEC-bench Pro漏洞发现88.2%、ExploitGym 54.8%、CWE-bench修复71.0%；并称内部团队已在跨天的复杂工程任务中使用它。以上是厂商披露的特定基准和内部经验，不能解释为所有企业环境的真实成功率。官方表示本周先向部分安全防御合作方开放，随后扩大可信合作伙伴范围，尚未向普通开发者全面开放。公告给出的未来定价为每百万输入Token 2美元、输出10美元，不能据此认定目前已普遍可购买。

**实践价值：** 安全Agent的评估至少分为 Finding Recall（发现）、Exploitability Evidence（可利用性证据）、Patch Correctness（修复正确性）、Regression（回归）四段；模型发现风险后不能自动视为已修复。  
**原始来源：** https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/

### 2.2 GitHub Copilot Fusion 正式GA：路由与编排合一

**主体：GitHub｜发布时间：2026-10-28｜新颖度：5/5｜状态：GA。**

Fusion 将自动模型选择与多模型编排结合，提供 Standard、High、Max 三档执行强度。核心执行模式：

| 模式 | 工作方式 | 适用任务 | 主要测试风险 |
|---|---|---|---|
| Single | 单模型直接完成 | 简单分类、查询、格式化 | 误选模型、错误工具 |
| Cascade | 轻模型先做，检查后升级 | 中等复杂度代码与问答 | 错误答案被错误放行 |
| Critique | 模型草拟、独立模型审阅、原模型修订 | 复杂代码审阅与分析 | 审阅者与生成者共性错误 |

GitHub披露 Fusion Max 在 Artificial Analysis Coding Agent Index 得分60，约为对比方案一半的平均API任务成本、约40%更短耗时。该结果来自指定基准，不能直接套用到内网Dify。Fusion按实际调用的模型计费，且企业管理员可限制允许路由的模型。

**金融测试启发：** 任务路由是优化层，不是授权层；即使选择了更强模型，也不得绕过Java权限校验。  
**原始来源：** https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion/

### 2.3 GitHub Agentic Workflows 正式GA：Markdown 到受控 Actions

**主体：GitHub｜发布时间：2026-10-28｜新颖度：5/5｜状态：GA。**

该项目把带Front Matter的Markdown任务定义编译成标准GitHub Actions YAML，支持Issue分诊、CI失败分析、文档维护、测试编写等。GA新增ARC自托管Runner/Docker-in-Docker、预算预测、模型路由、微虚拟机隔离等能力。默认Agent作业只读，变更通过受限Safe Outputs与独立安全检查执行。

**对当前日报归档的启发：** 将“检索—候选去重—内容验证—提交”拆成可检查阶段；写仓库的权限应与生成内容的权限分离，失败时不得报告假Commit SHA。

**限制：** 默认Copilot CLI引擎需相应Copilot许可；运行于GitHub Actions并不自动满足银行内网网络与数据合规要求。  
**原始来源：** https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/

## 5. Agent Ecosystem（3条）

### 5.1 Agent / Workflow：模型路由要先定义可验证的升级条件

Fusion的Cascade模式值得借鉴：轻模型先执行，Verifier检查证据，不满足阈值才升级。升级条件不宜仅使用模型自评置信度，至少要结合工具返回状态、业务字段完整性、权限拒绝、数据时间戳和结果一致性。

**建议流程：** 意图识别 → Capability白名单 → Java权限校验 → 查询 → Verifier → 回答或澄清。简单查询和复杂分析可走不同执行预算，但不得改变权限规则。

### 5.2 Skill / MCP：工具接入和仓库写入分层

GitHub Agentic Workflows通过只读Agent、Safe Outputs、独立威胁检测实现写入控制。对MCP/Skill也应区分工具发现、调用授权、参数审查、真实执行和副作用验证。Skill描述的是能力，不是业务权限。

建议保留：capability_id、tool_schema_version、skill_version、policy_version、trace_id、approval_hash。

### 5.3 Browser Agent / 安全治理：本地模型不等于离线执行

Fusion的本地模型路由仍需要云端路由决策；在银行受限内网，不能因“模型本地运行”就认为链路符合离线要求。Browser Agent还应限制文件上传、外部网络出口、凭据暴露与重复提交。

**本周最值得体验：** 使用Mock数据对同一组执行统计查询比较固定流程与“先验证、失败再升级”的Cascade流程，记录准确率、耗时和模型调用次数。

**Agent 实践启发：** 路由器负责资源选择，Verifier负责正确性，Java负责权限；三者不能由同一模型的自述代替。

## 9. 今日实战（1条）

### 给测试经理智能助手设计“任务分级 + 确定性验收”的轻量路由

保留现有 Vue3 iframe + Dify Chatflow + DeepSeek V4 + Java Capability API + PostgreSQL。先不引入新模型或复杂Agent框架，只在Dify中建立可观察的路由标签：

| 任务类型 | 例句 | 建议路径 | 必须验证 |
|---|---|---|---|
| SIMPLE_READ | 本月执行多少条？ | 固定Capability查询 | 权限、口径、时间范围 |
| RELATION_READ | 支付系统负责人是谁？ | 负责人Capability查询 | 关系有效期、权限 |
| CLARIFY | 张三的情况呢？ | 基于上下文补足参数或澄清 | 指代唯一性、用户身份 |
| DENY | 查询无权访问系统的全部人员数据 | Java拒绝 | 无真实数据泄露 |
| UNSUPPORTED_WRITE | 帮我修改系统负责人 | 不调用写接口 | 无业务副作用 |

**建议记录：** request_id、intent、route、capability_id、policy_decision、verifier_result、latency_ms、model_calls、trace_id。  
**关键原则：** 不让Dify根据“模型认为没问题”绕过Java权限；结果核验不通过时返回澄清或错误，而不是用更强模型猜测数据库事实。

## 10. Today Worth Thinking

> **模型路由能让任务更便宜，但如果廉价模型把错误结果判为正确、导致跳过复核，系统真的更高效吗？**

建议把优化目标从“单次请求成本”改为“每个独立验证通过任务的总成本”，纳入错误重试、人工复核和业务副作用。模型路由的质量门禁应独立于路由模型。

## 13. 我的备注：金融测试、Agent Testing与智能测试平台

### 测试经理智能助手

一期继续维持既定轻量集成，不因为Fusion或Carbon发布而改用新框架。最值得落地的是**固定业务Capability + 可观察路由 + 独立事实Verifier**。对于“本月执行数量”，统计口径必须在Java/SQL层定义；对于“负责人是谁”，需核对生效日期和数据权限。路由升级不能扩大权限。

### 日志脱敏检测平台

可以借鉴AI Scan“发现—修复—再次扫描关闭”的证据闭环：规则命中、AI精筛、人工确认、整改和同条件复扫应分别留痕。继续扫描和失败重扫要验证execution_epoch与event_id幂等，避免旧回调覆盖当前轮次；UNKNOWN不能自动归为误报。

### Agent Testing

建议新增四类质量指标：

| 指标 | 验证内容 |
|---|---|
| Route Accuracy | 任务是否选择正确能力路径 |
| Verifier Escape Rate | 错误结果是否绕过独立验收 |
| Cost per Verified Task | 每个通过验证的任务总成本 |
| Permission / Side-effect Integrity | 越权是否拒绝、写入是否可对账 |

**今日结论：模型路由和Agent编排可以提高效率，但生产级Agent的价值必须由独立业务验收、权限控制和可追溯证据来证明。**
