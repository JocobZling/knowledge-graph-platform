# AI 与 Agent 每日简报 v2

**日期：2026-08-21**

## 1. 今日摘要

近 24 小时最明确的高价值新增来自 Anthropic：8 月 20 日，Claude Platform 的 Computer Use、Skills API、Files API 正式 GA，同时 Computer Use 新增 Browser Use Tool。Browser Use 不再只依赖截图坐标，还结合页面结构定位元素；Computer Use 支持单轮执行多个动作，Skills API 支持上传与版本化团队流程，Files API 则承担跨请求文件存储与复用。

这组能力的意义不是“Claude 更会点网页了”，而是生产 Agent 的执行面正在从 API / MCP 继续扩展到没有 API 的 Web 和桌面软件。对于 Agent Testing，新问题随之出现：页面状态变化后批量动作是否仍安全、Skill 版本是否可追溯、文件生命周期是否正确、浏览器动作产生副作用后失败如何恢复。

第二条主线是 Agent Harness。TrueFoundry 近期正式开源 TrueForge，强调模型、MCP、Sandbox、Approval、Context、Session State 由独立 Runtime 管理。GitHub 实时查询时项目约 2,480 Star，MIT License。相比近几日日报已经讨论的 Policy Gate、Runtime Monitor 与 Control Effectiveness，今天更值得关注的是：Harness 本身正在成为可替换、可自托管、可评测的基础设施层。

最近 7 篇日报已覆盖 Gemini 3.7 Flash、Skill 供应链、Multi-Agent 监督、Policy Gate、A2A、Runtime Monitoring 与 Control Effectiveness，本期不重复，重点转向 **Computer/Browser Agent Reliability + Harness Engineering**。

## 2. AI / 大模型 Top News

### 2.1 Anthropic：Computer Use、Skills API、Files API 正式 GA

8 月 20 日，Anthropic 宣布 Computer Use、Skills API、Files API 在 Claude Platform GA。Computer Use 现在支持一次模型调用发出多个动作，减少长流程中的模型往返；同时新增 Browser Use Tool，可利用页面结构而不仅是像素坐标操作 Web 应用。

来源：https://claude.com/blog/computer-use-skills-api-files-api

实质变化是 Agent 的执行接口开始形成四层：

```text
API / MCP Tool
      +
Browser DOM / Page Structure
      +
Computer UI / Pixels
      +
Files / Skills
```

对于企业自动化，这意味着过去“系统没有 API，所以不能自动化”的边界继续缩小。

### 2.2 Browser Use：从坐标点击进入结构感知操作

新的 Browser Use Tool 会同时读取页面结构并定位具体字段或按钮。相比只看截图再计算坐标，这种方式理论上更能抵抗页面布局轻微变化。

但新的测试面也更清楚：DOM/结构信息与视觉信息冲突怎么办？隐藏元素是否可能被错误操作？页面更新后 Agent 是否仍基于旧状态继续执行？

尤其当 Computer Use 支持 Multi-action Turn 后，一次调用可能连续 click → type → submit。效率提高的同时，前一步失败会把后续动作建立在错误状态上。因此 Browser Agent 需要专门测试 **State Drift 与 Batch Action Failure**。

### 2.3 Skills API + Files API：流程知识与工作文件进入 Agent Runtime

Skills API 允许上传、版本化并在请求中绑定 Skill；Skill 由说明、脚本和模板组成，并在代码执行 Sandbox 中运行。Files API 支持文件一次上传、后续按 ID 复用，并增加自动过期、更高限流与每组织 1 TB 存储。

来源：https://claude.com/blog/computer-use-skills-api-files-api

这使生产 Agent 更像一个完整工作环境：

```text
Skill = Procedure
File = Working State
Browser = Execution Surface
Model = Decision Engine
```

因此版本、权限、文件过期和执行 Trace 都应该进入同一条审计链。

### 2.4 TrueForge：开源 Harness 把 Agent Runtime 独立出来

TrueFoundry 近期开源 TrueForge，定位为 vendor-neutral Agent Harness。它负责 Agent Loop、MCP Tool、Skill、Sandbox、Approval、Context Management 与 Session State，并允许自托管和替换模型供应商。

来源：https://www.truefoundry.com/blog/engineering/trueforge-open-source-agent-harness/
项目：https://github.com/truefoundry/trueforge

TrueFoundry 公布的自有 benchmark 称，在其 14 个 production-style tasks 上，相同模型可降低约 30% 成本，切换开放模型时最高降低约 75%；这些属于厂商测试结果，不应直接外推到其他 Workflow，需要独立复测。

## 3. 科技行业动态

### 3.1 GUI Automation 与 Agent 正式合流

过去 RPA 主要依赖固定 Selector / Script，Agent 主要依赖 Tool/API。现在二者正在汇合：模型负责理解页面与目标，Browser/Computer Tool 负责执行。

这意味着测试也必须同时覆盖 **语义正确性 + UI 状态机 + 副作用**。最终页面显示“成功”并不足够，还要验证 Agent 是否点击了正确对象、是否重复提交、是否越过确认页、是否在失败后错误重试。

### 3.2 Harness 正在成为模型之外的第二个核心变量

TrueForge 的出现强化了一个趋势：同一个模型放进不同 Harness，实际 Agent 的成本、上下文保持、Tool 行为、审批机制和恢复能力可能明显不同。

因此后续 Agent Benchmark 更合理的比较单位应是：

```text
Model × Harness × Toolset × Policy × Dataset
```

而不是只比较 Model。

## 5. Agent Ecosystem

### 本周最值得体验：Browser Agent State-Drift Test

选择一个至少三步的网页流程：

```text
填写字段
→ 下一步
→ 确认
→ 提交
```

在第二步人为制造页面变化，例如弹窗、加载延迟、字段校验失败。

观察 Agent 是否重新感知状态，还是继续执行原先规划好的后续动作。

### Agent 实践启发：Batch Action 需要事务思维

多动作一轮可以显著减少延迟，但越靠后的动作越依赖前序状态。

因此高风险操作不适合无限 Batch：

```text
低风险导航 → 可 Batch
填写普通字段 → 可有限 Batch
确认 / 提交 / 删除 / 支付 → 强制重新观察 + Policy Check
```

### Workflow 治理：把 UI Action 也纳入 Trace

建议记录：

```yaml
page_state_before: hash-001
actions:
  - click: next
  - type: amount
page_state_after: hash-002
high_risk_action: submit
approval_required: true
business_assertion: passed
```

这样 GUI Agent 才能像 API Agent 一样复盘。

## 7. 企业实践

### Slack：把 Agent 放进公开协作上下文，而不是孤立聊天框

Anthropic 8 月 19 日发布与 Slack CPO Jaime DeLanghe 的实践访谈，核心思路是利用公开 Channel 中持续积累的对话、决策和工作过程，让 Agent 能基于团队共享上下文参与协作，而不是只依赖某个人与 AI 的私聊历史。

来源：https://claude.com/blog/turning-conversation-into-knowledge-how-slack-builds-human-agent-teams

可借鉴点是：企业 Agent 的 Context 不应只考虑“能塞多少 Token”，还要考虑 **哪些上下文是组织可共享、可追溯、可搜索的正式知识**。

## 8. 今日工具推荐

### TrueForge

今天建议把它当作 Harness 研究样本，而不是立即迁移平台。

重点看四件事：

1. Sandbox 为什么作为按需 Tool 而不是 Agent 全程环境；
2. Context Compaction 如何减少长任务成本；
3. Human Approval 在什么动作前暂停；
4. Session State 如何跨断线/重启保存。

## 9. 今日实战

给一个 Browser Agent 增加“高风险动作前重新观察”规则：

```text
普通点击 / 输入
      ↓
页面状态可能变化
      ↓
重新 Screenshot + Page Structure
      ↓
确认目标仍一致
      ↓
Policy Check
      ↓
Submit
```

然后制造一次按钮位置变化或表单校验失败。

关键断言不是“最后有没有成功”，而是：**Agent 是否在提交前重新确认了真实页面状态。**

## 10. Today Worth Thinking

Agent 越来越会操作真实软件以后，可靠性问题会发生变化。

API Tool 通常有明确 Schema 和返回码；GUI 却充满弹窗、延迟、动态布局、半完成状态和不可逆按钮。

因此 Computer Use 的核心测试问题可能不是：

> 它会不会点按钮？

而是：

> **它是否知道自己刚才那一步到底有没有成功？**

## 11. 30分钟 Action

今天挑一个真实但无副作用的内部 Web 流程，手工写 5 个 Browser Agent Case：

1. 正常流程；
2. 页面加载慢；
3. 弹窗遮挡；
4. 字段校验失败；
5. 点击成功但页面未跳转。

每条只记录三个指标：

**State Recognition / Recovery / Duplicate Action。**

这已经是一份最小 Browser Agent Reliability Set。

## 13. 我的备注

结合金融测试、Agent Testing 和智能测试平台，今天最值得新增的是 **GUI / Browser Agent 测试域**。

过去 Agent Testing 可以主要围绕：

```text
Model
→ Tool / MCP
→ Result
```

以后需要补成：

```text
Model
→ Harness
→ Browser / Computer
→ UI State
→ Action
→ Side Effect
→ Business Assertion
```

金融系统里大量后台管理、运营、测试辅助页面并不一定有适合 Agent 的标准 API。Computer Use 确实可能让 Agent 很快进入这些系统，但不能因此直接把“人能点的按钮”全部开放给 Agent。

建议先把 UI 动作分三级：

```text
L1 浏览 / 查询 / 翻页
L2 填写但不提交
L3 提交 / 删除 / 状态变更 / 资金相关
```

L1 可以允许更积极的批量动作；L2 在关键字段后重新感知；L3 强制重新观察、Policy Gate、幂等和必要的人审。

这样测试平台后续就可以统一比较 API Agent 与 Browser Agent：前者重点看 Tool Schema 和权限，后者额外看 UI 状态识别、重复动作和副作用。最终不管 Agent 是通过 MCP、A2A 还是“点网页”完成任务，都回到同一套 Trace + Business Assertion 上。
