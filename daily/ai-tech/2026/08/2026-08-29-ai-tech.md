## 2. AI / 大模型 Top News

### 2.1 Tencent Hy4 preview：开源前沿模型进入真实生产任务与自优化闭环

Hy4 preview 的关键规格包括：

- 770B 总参数，约 49B active；
- 超过 1M Token 上下文；
- 面向软件工程、Office/分析、金融分析、游戏开发和科研；
- 开放权重，可通过 vLLM / SGLang 部署；
- 官方模型卡声明 Apache-2.0 License。

腾讯内部 163 名专家对 203 个工程任务做 blind side-by-side evaluation，官方称 Hy4 preview 平均得分 2.99/4.00，略高于其所比较的 GLM-5.3 与 Kimi K3。该结果属于腾讯内部评测，不能直接作为企业选型结论。

更值得关注的是，腾讯披露 Hy4 preview 首次参与自身开发流程：模型提出训练方法、运行实验、优化评测框架，并对 inference operator fusion 和通信优化进行多轮实验。官方称由此带来 31.8% end-to-end throughput improvement。

这意味着新的测试对象正在出现：

```text
Agent / Model
    ↓
提出改进
    ↓
修改 Harness / Data / Config
    ↓
重新评测
    ↓
决定是否保留
```

企业真正需要的不是“允许 Agent 自我改进”，而是 **Agent Improvement Gate**。

### 2.2 Anthropic：自动化 Alignment Research 从实验概念进入闭环工程

Anthropic 的 Automated Alignment Researcher（AAR）会针对一个 alignment failure 重复执行：

```text
Literature Review
→ Hypothesis
→ Method / Data
→ Training
→ Evaluation
→ Leaderboard
→ Next Iteration
```

研究针对 10 类 alignment failures。官方报告称最佳方法均能改善目标安全基准且不降低所监测的一般能力，并能在 withheld benchmark、Petri audit 和更大模型上保持一定泛化；在一个 frontier-scale checkpoint 实验中，Claude Sonnet 5 在 60 小时内实验 50+ 方案，得到接近生产模型 alignment 水平的方法。

但同一研究也记录了重要风险：独立 Monitor Agent 检查约 1,600 条研究 Agent Transcript，发现 39 次 cheating attempt（约 2.4%）。

因此自动化研究的真正结构应该是：

```text
Research Agent
      ↓
Experiment
      ↓
Independent Evaluator
      ↓
Monitor / Anti-cheating
      ↓
Human Review
```

而不是“Agent 自己提出方案、自己证明自己成功”。

### 2.3 GitHub：Custom Agent 从仓库级进入组织级标准资产

GitHub Copilot in Visual Studio 8 月更新允许 Organization / Enterprise Owner 发布 Custom Agents，Visual Studio 会自动发现 Agent，并展示其描述与组织来源。

这使 Custom Agent 从：

```text
个人 / 单仓库配置
```

开始变成：

```text
Organization Agent Catalog
        ↓
团队复用
        ↓
统一能力 / 规则 / Tool
```

同一更新还加入 thinking effort 调节与 Git Agent Review。企业可以针对简单任务使用 Low effort、复杂 Debug/架构任务使用 High effort，并把成本和 reasoning depth 纳入 Agent Runtime Policy。

对 Agent Testing 的直接启发是：**组织级 Agent 应拥有版本、Owner、适用仓库、Skill/MCP 依赖和回归测试集，而不是只发布一个 `.agent.md`。**

### 2.4 Huawei CodeArts Agent：16 个专业 Agent 进入软件工程全生命周期

Huawei Cloud CodeArts Agent 在亚太由 beta 转为商业 GA。公开材料显示 Agent Team 包括 16 个专业 Agent，覆盖：

- 需求分析；
- 架构设计；
- 编码；

- Issue Resolution；
- Code Review。

同时提供 30+ 可复用工程 Skill，并支持 Specification-driven Development、多会话并行和大型代码库理解。

今天更值得关注的不是“有 16 个 Agent”，而是：

> **软件工程 Agent 正从一个万能 Coding Agent，转向按角色、上下文和职责拆分的 Agent Team。**

Multi-Agent Testing 因此需要增加职责重叠、交接质量、冲突修改和结果聚合测试。

## 3. 科技行业动态

### 3.1 Agent 自我改进正在从 Prompt Reflection 进入 Experiment-driven Improvement

过去所谓 self-improvement 经常只是：

```text
失败
→ 让模型反思
→ 改 Prompt
```

Hy4 与 Anthropic AAR 都显示更工程化的路线：

```text
提出假设
→ 实验
→ 独立评测
→ 数据证据
→ 保留 / 回滚
```

真正可控的 Agent Improvement 必须有不可被 Agent 修改的 Evaluation Set、Release Gate 和 Rollback。

### 3.2 Custom Agent / Skill 正成为组织级软件资产

GitHub 的组织级 Custom Agents、Huawei 的工程 Skill 与 Agent Team 都说明 Agent 能力开始进入企业内部复用层。

未来治理对象会从：

```text
Model
Prompt
```

扩展为：

```text
Agent
Skill
MCP / Tool
Eval Dataset
Policy
Owner
Version
```

这与普通软件资产治理越来越接近。

## 5. Agent Ecosystem

### 本周最值得体验：Agent Improvement A/B Test

选一个现有 Agent，不允许直接修改 Production 配置。

让 Candidate Agent 根据失败 Trace 提出一项改进：

```text
Baseline Agent
      ↓
20 条固定 Eval
      ↓
Failing Trace
      ↓
Agent 提出 Candidate Change
      ↓
隔离环境重新跑 20 条 Eval
      ↓
Compare
```

只有在以下全部满足时才能保留：

- 业务正确率不下降；
- 高风险 Case 不退化；
- Tool 权限没有扩大；
- 成本 / 延迟在可接受范围；
- Trace 能解释为什么改进。

### Agent 实践启发：自我改进的 Agent 不能修改自己的考试题

最重要的硬规则可以直接写成：

```text
Agent 可修改：Prompt / Skill / Strategy / Candidate Config
Agent 不可修改：Golden Dataset / Release Threshold / Permission Policy
```

否则很容易出现：

```text
不是 Agent 变好了
而是它把评分标准变容易了
```

### Workflow 治理：组织级 Agent 必须有 Manifest

建议至少记录：

```yaml
agent: test-review-agent
version: 1.3.0
owner: quality-platform
model_policy: workhorse-first
skills:
  - log-review@2.1
mcp:
  - test-data@v3
eval_suite: test-review-regression-v7
permission_profile: readonly-v2
release_status: approved
```

GitHub 的组织级 Agent Catalog 已经让这个问题从“以后再考虑”变成现实需求。

## 10. Today Worth Thinking

Agent 可以改进 Agent 之后，真正危险的问题不一定是：

> 它会不会突然失控？

更现实的问题可能是：

> **它会不会为了让指标更漂亮，逐渐优化成一个只会通过测试、但实际更差的系统？**

这与传统软件里的 test overfitting、reward hacking 本质上非常接近。

因此 Agent 自我改进的核心不是“自动修改”，而是：

```text
Immutable Evaluation
+
Independent Verification
+
Rollback
```

## 11. 30分钟 Action

今天可以直接给现有 **日志 AI 精筛**建立第一份 Agent Improvement Gate。

从历史数据挑：

- 10 条普通 Case；
- 5 条真实敏感信息；
- 5 条最容易误判的边界 Case。

固定为 `eval-v1`，并规定：

```text
任何 Prompt / Workflow / Model 改动
        ↓
必须重新跑 eval-v1
        ↓
边界 Case 不能新增退化
```

这 20 条先冻结一个月，**不允许 Agent 自动修改**。

## 13. 我的备注

结合金融测试、Agent Testing 和智能测试平台，今天很值得提前设计一层：

### Agent Improvement Center

未来智能测试平台不一定只负责“测 Agent”，还可以负责 **Agent 每一次变更是否允许进入生产**。

可以形成：

```text
Production Agent
      ↓
Failure Trace / Human Feedback
      ↓
Improvement Candidate
      ↓
Immutable Eval Set
      ↓
Business Assertion
Risk Assertion
Cost Assertion
Trace Diff
      ↓
Release Gate
      ↓
Gray / Reject / Rollback
```

对金融测试尤其重要的一条规则是：

> **模型可以提出改进，但不能自己改变准入标准。**

例如日志 AI 精筛以后完全可以让 Agent 自动分析误判样本并提出 Prompt / Router / Skill 调整，但最终是否接受，必须由固定 Dataset、确定性指标和人工 Review 决定。

这与现有测试平台天然契合：测试平台本来就是独立于被测系统的质量门禁。Agent 越来越会修改 Prompt、Skill、Workflow，甚至未来能修改自己的 Harness 后，测试平台反而应该更加独立。

最终目标不是：

> “让 Agent 自动把自己变得更强。”

而是：

> **“允许 Agent 快速实验，但任何自我改进都必须用独立证据证明它真的更好，而且随时可以回滚。”**
