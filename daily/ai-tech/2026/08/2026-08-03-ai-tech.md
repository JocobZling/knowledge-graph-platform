# AI 与 Agent 每日简报 v2

**日期：2026-08-03**

## 1. 今日摘要

近24小时没有出现新的旗舰模型或大型Agent产品GA。真正具有新增价值的变化来自监管执行节点：欧盟AI法案多数规则自8月2日起进入适用和执法阶段，通用人工智能模型（GPAI）相关义务开始由“协作整改期”转入可处罚的正式执行期；欧盟官方FAQ同时明确，AI Agent虽然不是单独法律类别，但通常会同时落入AI系统与GPAI模型相关规则范围。

最近7篇日报已覆盖MCP无状态化、Skill动态发现、Browser Agent识别、长任务安全、AgentCore评测和GitHub Agent治理，本期不重复这些能力，仅保留出现正式执法节点的新进展。

## 2. AI / 大模型 Top News

### 2.1 欧盟AI法案多数规则开始适用，执法正式启动

欧盟AI法案实施时间表显示，自2026年8月2日起：

- 多数规则进入适用阶段；
- Article 50透明度规则开始适用；
- 欧盟及成员国层面的执法启动；
- 对GPAI模型、禁止性实践、AI素养与透明度义务的执行进入实质阶段。

来源：
- https://ai-act-service-desk.ec.europa.eu/en/ai-act/eu-ai-act-implementation-timeline

对企业Agent平台而言，影响不是新增一份合规文档，而是要求运行系统能够持续生成可验证证据。

```text
模型资料
+ Agent组件清单
+ Tool / MCP权限
+ 用户透明度提示
+ 执行轨迹
+ 风险评测
+ 事件报告
+ 人工接管
```

### 2.2 欧盟明确：AI Agent通常已被现有AI系统规则覆盖

欧盟AI Act Service Desk FAQ指出，AI Agent虽未被单独定义为法律类别，但通常至少包含GPAI模型和系统接口，因此现有AI系统与GPAI模型规则足以覆盖Agent。

自8月2日起，与自然人交互或生成内容的Agent需要重点关注Article 50透明度要求，包括：

- 用户是否清楚正在与AI交互；
- AI生成或修改内容是否按要求披露；
- Agent执行的关键动作是否可追踪；
- 下游业务系统是否获得模型能力与限制信息。

来源：
- https://ai-act-service-desk.ec.europa.eu/en/faq

### 2.3 GPAI模型义务进入可处罚执行期

欧盟委员会此前给予GPAI模型提供方一年的协作合规窗口。自2026年8月2日起，委员会开始全面执行相关义务，包括：

- 维护模型技术文档；
- 向下游系统提供能力与限制信息；
- 建立版权合规政策并公布训练内容摘要；
- 对系统性风险模型执行风险评估与缓解；
- 建立严重事件报告和网络安全保护机制。

来源：
- https://digital-strategy.ec.europa.eu/en/faqs/guidelines-obligations-general-purpose-ai-providers
- https://digital-strategy.ec.europa.eu/en/policies/guidelines-gpai-providers

对Agent Testing的直接影响是：模型评测报告不能停留在Benchmark分数，应能映射到具体Agent场景、工具权限和风险缓解措施。

路透社7月30日报道，美国政府官员正与OpenAI等企业讨论高级AI系统自愿网络安全测试框架。该讨论发生在近期自主Agent越界和外部系统攻击事件之后，重点关注高级模型与Agent的网络能力、安全测试和政府协同。

## 3. 科技行业动态

### 3.1 Agent治理从原则声明进入证据化执行

过去企业常用政策、伦理原则和模型卡证明治理能力。正式执法阶段更关注可验证证据：

- 哪个Agent调用了哪个模型与Tool；
- 使用了什么身份和业务范围；
- 是否向用户披露AI身份；
- 哪个风险规则允许、拦截或转人工；
- 发生异常后多久发现、暂停与报告。

因此，Agent Trace将同时成为质量证据、安全证据和合规证据。

### 3.2 合规责任沿模型供应链向下传递

GPAI模型提供方需要向下游提供能力和限制信息；下游Agent平台则需要证明自己如何将这些限制落实到：

- 场景准入；
- Prompt与Skill配置；
- Tool权限；
- 数据范围；
- 人工监督；
- 回归评测。

模型合规不自动等于Agent系统合规。

### Agent实践启发：透明度不能只放在页面角落

Agent透明度应覆盖整个链路：

- 交互开始时声明AI身份；
- 自动执行动作前提示执行主体与范围；
- 生成报告中标注AI参与程度；
- 人工修改与AI生成内容可区分；
- 审计系统记录用户是否获得提示。

### Workflow安全治理

高风险Agent Workflow应增加独立的合规门：

```text
任务准入
→ 身份与权限校验
→ AI透明度确认
→ Tool调用
→ 业务断言
→ 风险复核
→ 证据归档
```

## 9. 今日实战

### 为Agent增加透明度与证据完整性检查

```python
REQUIRED_EVIDENCE = {
    "agent_identity_notice",
    "model_version",
    "tool_permissions",
    "trace_id",
    "business_assertion",
    "human_oversight",
}


def validate_evidence_pack(pack: dict) -> dict:
    missing = sorted(REQUIRED_EVIDENCE - pack.keys())
    return {
        "passed": not missing,
        "missing": missing,
        "traceable": bool(pack.get("trace_id")),
        "business_verified": pack.get("business_assertion") == "passed",
    }
```

该检查应在报告归档或任务标记成功前执行。

## 10. Today Worth Thinking

过去企业常问：

> 模型是否安全？

进入Agent执行时代后，更准确的问题是：

> 这个Agent在特定身份、数据、工具、场景和流程约束下，是否持续表现得安全、透明、可审计？

Agent系统的风险不是模型风险的简单复制，而是：

```text
模型能力
× Tool权限
× 数据范围
× 运行时长
× 自动化程度
× 人工监督缺口
```

因此，Agent Testing必须同时覆盖模型、Workflow、Tool、权限、业务结果和证据链。

```text
任务输入
→ 用户与Agent身份
→ 模型版本
→ Skill / MCP / Tool
→ 权限与数据范围
→ 执行轨迹
→ 业务断言
→ 风险判定
→ 人工监督
→ 最终报告
```

近期最有落地价值的不是再增加一个Agent，而是先让一个金融测试Agent具备完整、自动生成、可回放的Evidence Pack。这样既能支持日常质量复盘，也能为后续模型准入、安全审查和监管检查提供同一套底层证据。
