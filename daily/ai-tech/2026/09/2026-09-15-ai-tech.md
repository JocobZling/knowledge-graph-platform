# AI 与 Agent 每日简报 v2

**日期：2026-09-15**

## 1. 今日摘要

最近7日日报已完成主题去重。9月14日已重点覆盖 Independent Evaluation、Agent Monitoring、Independent Evidence Gate、DAREBench 与 MCP Apps；更早几日已覆盖 Guardian/Gateway、Incident Forensics、Background Agent、Durable Approval、Identity Continuity 等，因此今天不重复这些主线。

过去24小时最值得保留的变化集中在“专业工作流 + 生产自治 + 动态模型路由”。Anthropic 9月14日推出 Claude for Financial Advisors，通过面向投顾日常工作的 Workflow Skills 和连接器接入 BlackRock、Charles Schwab、Addepar 等金融/财富管理数据与工具；OpenAI 同日披露 Perplexity 已让 GPT-6 Astra 承担写通信、改软件、监控生产系统等端到端任务，并降低人工检查频率；GitHub Copilot 自动模型选择新增 efficiency、balance、intelligence 三档，使成本、质量、延迟之间的路由策略成为显式产品能力。

今天的主线是：**Agent 的下一阶段不只是“更自主”，而是把专业任务契约、数据权限、模型路由和验证证据一起工程化。**

## 2. AI / 大模型 Top News

### 2.1 Claude for Financial Advisors：金融 Agent 从问答进入专业 Workflow

Anthropic 9月14日推出 Claude for Financial Advisors，目标包括客户会议准备、组合审查与后续工作，并通过金融数据/财富管理连接器和 Workflow Skills 把 Claude 接入真实专业流程。对金融测试而言，测试对象不再只是回答准确率，而应扩展为 `Client Scope → Data Source → Workflow Skill → Generated Artifact → Human Review` 的完整任务链。

### 2.2 Perplexity：Astra 开始承担端到端生产任务

OpenAI 公开案例显示，Perplexity 使用 GPT-6 Astra 写通信、修改软件并监控生产系统，人工检查频率较此前模型降低。真正值得关注的是 Human Check Frequency 正在下降：能力提升以后，控制面不能简单同步减少，而应把人工检查转化为基于风险、变更范围和证据质量的动态 Gate。

### 2.3 GitHub Copilot：模型路由策略产品化

Copilot Auto Model Selection 新增 efficiency、balance、intelligence 三档，让系统按成本、质量和响应速度自动选择模型。企业 Agent 因此需要把“模型是谁”从固定配置改造成运行时事实，并保存 `routing_policy / selected_model / reason / cost / latency / outcome`，否则事故回溯时无法解释同一 Prompt 为什么产生不同表现。

### 2.4 Fyxer：复杂 Agent Workflow 的价值可能来自任务拆分而非单一超长 Prompt

OpenAI 最新案例披露 Fyxer 将邮件助理拆成更小的任务，并结合模型、微调、Memory 与真实用户反馈；其公开数据称90天用户留存约90%，53%的AI草稿无需修改即被接受。对 Agent 工程的启发是：专业可靠性往往来自任务分解、反馈闭环和局部可验证步骤，而不是单纯换更大的模型。

## 3. 科技行业动态

### 3.1 Vertical Agent 正从“行业 Prompt”走向“行业连接器 + Skill + 权限”

Claude for Financial Advisors 的关键不是金融版 System Prompt，而是连接真实数据源、专业 Workflow Skills 与企业权限体系。Vertical Agent 的竞争壁垒会越来越集中在数据接入、业务语义、流程契约和审计，而不是 UI。

### 3.2 Agent 成本优化开始从 Token 单价走向 Runtime Routing

GitHub 的三档 Auto Model Selection 与近期多个 Harness 实践说明，生产系统正在把不同模型当作可调度资源。未来更有意义的指标是 `Cost / Successful Task`、`Latency / Successful Task` 和 `Escalation Rate`，而不是单纯比较输入输出 Token 单价。

## 5. Agent Ecosystem

### 本周最值得体验：Model Routing Regression

固定20个真实任务，分别运行 efficiency、balance、intelligence 三种策略，记录：`selected_model / task_success / tool_error / latency / token / human_rework`。重点不是找“最好模型”，而是验证路由策略是否真的把简单任务送给低成本模型、复杂任务送给高能力模型。

### Agent 实践启发：Task Contract 比 Prompt 更适合作为专业 Agent 的稳定边界

金融 Workflow 建议明确：输入对象、允许数据源、输出物、禁止动作、必须证据、人工复核点。模型和 Prompt 可以升级，但 Task Contract 应保持稳定并进入版本控制。

### Workflow 治理：动态路由后必须记录实际模型

如果 Agent 自动选择模型，Trace 中不能只保存 `model=auto`。至少保存 `routing_policy_version`、`selected_model`、`selected_model_version`、`fallback_chain` 和最终 Outcome，才能支持回归和事故定位。

## 9. 今日实战

给现有 AI Workflow 增加 `task_contract`：

```yaml
task_contract:
  task_type: ai_log_review
  allowed_sources: [scan_result, log_context]
  allowed_actions: [write_ai_review]
  forbidden_actions: [update_rule_status, delete_report]
  required_evidence: [rule_hit, context]
  human_gate: false
```

模型只负责在 Contract 内完成任务；业务服务在真正写入前验证 Contract。

## 13. 我的备注

对金融测试和现有智能测试平台，今天最值得落地的是把 **Task Contract、Model Routing、Evidence** 三件事拆开。

AI 精筛现在可以定义稳定 Task Contract：只能读取规则命中、上下文和配置，只能写 AI Review Result，不能修改规则扫描事实。未来无论底层切换 GPT、DeepSeek 或内部模型，这个 Contract 都不变。

第二，模型选型不要全平台固定一个模型。地址类、密码类、复杂上下文、普通结构化规则可以逐渐形成 Workload Profile，再分别统计 Accuracy / Cost / Latency / Human Review。等数据足够后再做动态路由。

第三，每一次动态路由都必须进入 Trace：`prompt_version + routing_policy + selected_model + task_contract + evidence + outcome`。这样模型自动切换以后，测试平台仍然能回答：这条结果是谁判断的、为什么选择这个模型、它看了什么证据、最终写了什么。

这套设计会比“统一换更强模型”更适合银行环境：模型可以快速演进，但业务边界、证据和审计保持稳定。
